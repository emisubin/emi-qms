## 2. 변경된 최종 결론

- 현재 별도 선택 동의 대상은 **프로필 사진 1건**이다.
- 프로필 사진은 핵심 QMS 업무 수행에 필수적이지 않고 사용자가 직접 등록·교체·삭제하는 선택 정보다.
- 이름·업무 이메일·부서·역할, 업무·감사 기록, 검사·조치 사진과 첨부, Teams·메일 업무 알림, 로그인 유지·PWA 기능은 별도 선택 동의 항목으로 만들지 않는다. 실제 처리 목적·항목·근거·보유기간은 개인정보 처리방침에 고지한다.
- 향후 Web Push를 구현하면 현재 결정에 포함하지 않고 별도 opt-in·기기 권한·철회 정책을 신규 기능에서 결정한다.

## 3. 프로필 사진 동의 UX

별도 동의 페이지나 회원가입 차단 화면을 만들지 않는다. 사용자가 계정 메뉴의 `사진 변경`을 누를 때만 desktop에서는 dialog, mobile에서는 같은 내용의 bottom sheet를 표시한다.

### 표시 문구

**제목**

`프로필 사진 선택 동의`

**본문**

> 프로필 사진은 계정 식별과 화면 표시를 위해 선택 수집합니다.
>
> 등록한 사진은 사진을 삭제·교체하거나 퇴사할 때까지 보관합니다. 동의하지 않아도 기본 이니셜로 모든 업무 기능을 이용할 수 있습니다.

**Action**

- 보조 action: `취소`
- 주 action: `동의하고 사진 선택`

### 동작

1. `사진 변경`을 누르면 파일 선택기를 바로 열지 않고 동의 안내를 먼저 표시한다.
2. `취소`를 누르면 아무 정보도 수집하지 않고 계정 메뉴로 돌아간다.
3. `동의하고 사진 선택`을 누른 경우에만 기존 JPEG·PNG 파일 선택과 5MB 검증을 진행한다.
4. 사진을 교체할 때마다 같은 안내를 다시 표시한다. 전역 동의 상태나 별도 동의 DB를 만들지 않는다.
5. `사진 제거`는 추가 동의 없이 실행하며 사진 원본을 삭제하고 기본 이니셜로 복원한다.
6. 동의하지 않거나 철회해도 로그인·권한·업무·알림 기능에는 불이익이 없다.

## 4. 구현 불변조건

- 선택 동의는 프로필 사진 업로드에만 적용하고 앱 로그인·일반 이용의 필수 동의로 만들지 않는다.
- 미리 선택된 checkbox, 포괄 문구와 거부 시 서비스 차단을 사용하지 않는다.
- 기존 profile photo upload/remove authorization, 파일 검증, 본인 사진만 변경하는 계약과 audit event를 유지한다.
- 기존 업로드 audit 시각과 배포된 동의 문구의 Git 이력을 근거로 남기며, 이번 최소안에서는 신규 consent table·migration을 추가하지 않는다.
- 실제 구현 전 기존 프로필 사진 존재 여부를 개인정보 원문 없이 count로 확인한다. 기존 사진이 있으면 운영 게시 전에 재동의 또는 삭제 방식을 별도 change로 확정한다.

## 5. 회사 제공 정보의 privacy-safe 반영

- 법인 정식 명칭: 회사 확인 완료
- 개인정보 담당 및 문안 승인 부서: 영업CS팀
- 담당 연락 값: 사용자 대화에서 제공 완료. 개인 식별 가능 값이므로 Task 문서·검증 증빙에는 전사하지 않고, 회사 게시 승인 후 제품 문안 source에만 기재한다.
- 계정 정보 보유 기준: 퇴사 시까지
- 시범 운영 종료: 별도 삭제 없이 정식·계속 운영 데이터로 승계
- 업무 파일·기록: `사내 규정에 따름`으로 답변됨. 처리방침 게시 전 실제 규정명 또는 구체적인 기간·판단 기준을 추가 확인한다.
- 외부 서비스: 회사가 기존 Teams·메일 등 사용에 관해 검토 완료라고 확인함. 개인정보 처리방침에는 실제 Azure·Entra·Teams·메일 흐름의 위탁·제공·국외 이전 해당 여부를 구분해 기재한다.
