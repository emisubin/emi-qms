# DESIGN-000 Change 003 Implementation report — 업무·프로젝트·입력 화면 분리

## 1. 요약과 상태

- 목적: 다중 업무 부서에서 업무 선택, 업무별 현황, 실제 입력이 한 화면에 섞이지 않도록 `업무 선택 → KPI·프로젝트 선택 → 단일 프로젝트 입력`의 3단계 구조로 분리한다.
- 상태: `EXPERIMENT_COMPLETE / USER_VALIDATION_PENDING`
- 계약: [DESIGN-000 Change 003](design-000-change-003.md)
- 범위: 생산관리, 자재, 제조, 품질, 물류와 Pending의 메뉴 진입·프로젝트 선택·입력 화면 구조.
- 제외: API, DB, migration, 권한, 알림, Pending 수명주기, 업무 상태 전이, 입력 필드와 저장 로직, 대표 repo, `main`, push, PR, merge, Persistent UAT.
- UX/UI 평가 범위: 사용자 지시에 따라 PC만 평가했다. 모바일은 기존 동작의 회귀 방지만 유지하고 평가에서 제외했다.

## 2. 구현

- 생산관리는 `생산계획 / 제조 투입`, 자재는 `입고 관리 / 패널 키팅`, 품질은 `IQC / LQC / OQC / 전진검수 / FAT`, 물류는 `포장 / 출발 / 납품`을 세로 업무 목록에서 먼저 선택하게 했다.
- 업무를 고른 뒤에는 해당 업무만의 KPI와 프로젝트 목록을 표시하고, 프로젝트를 선택해야 상세 입력을 연다.
- 제조는 메뉴 진입 시 전체 작업을 바로 열지 않고 제조 KPI와 프로젝트 목록을 먼저 표시한다.
- 제조 프로젝트를 열면 선택한 프로젝트의 패널만 왼쪽 세로 목록에 표시하고 기존 제조 입력·일괄 조립 단계 완료·Excel 선택 기능을 유지한다.
- LQC·OQC·전진검수·FAT도 검사별 KPI와 프로젝트 목록을 먼저 표시하고, 선택한 프로젝트의 패널만 왼쪽 세로 목록에서 선택한다.
- IQC는 구매품목 도착분 단위를 유지하면서 프로젝트별 KPI·목록을 앞단에 추가했다.
- 키팅은 프로젝트 KPI·목록을 먼저 표시하고, 선택 프로젝트만 기존 키팅 입력으로 연다.
- 물류는 포장·출발·납품을 각각 독립된 KPI·프로젝트 페이지로 분리하고 기존 패널별 증빙·확정 로직을 그대로 사용한다.
- Pending은 단일 업무이므로 불필요한 업무 선택 화면을 제거하고 `진행 중·긴급·기한 초과·재검사 대기` KPI와 프로젝트 목록으로 바로 시작한다.
- Pending 프로젝트를 열면 프로젝트 선택 필터와 행마다 반복되던 프로젝트 링크를 제거하고, 해당 프로젝트의 KPI·필터·선택 내보내기·이슈를 compact한 한 열 구조로 표시한다.
- 목록에서 프로젝트 상세로 이동할 때 Pending 컴포넌트를 프로젝트 ID로 다시 초기화해 이전 프로젝트의 비동기 응답이 현재 프로젝트에 섞이지 않게 했다.
- 알림과 내 업무의 기존 deep link는 업무 허브를 거치지 않고 지정 프로젝트·패널 입력을 바로 연다.
- 프로젝트 행은 표 구조 안에서 명시적인 버튼으로 제공해 마우스와 키보드 모두 같은 방식으로 열 수 있게 했다.

## 7. PC UX/UI 평가와 사용자 검수 체크리스트

### 전체 PC 평가

- 전체 평가는 `7/10`이다. 업무 기능과 부서 간 흐름은 풍부하고 흑백 wireframe 규칙도 안정됐지만, 첫 화면 정보 밀도와 화면별 용어·빈 상태·보조 조작의 우선순위는 아직 다듬을 여지가 있다.
- 가장 좋아진 부분은 정보 구조다. 다중 업무 부서는 `업무 선택 → KPI·프로젝트 → 한 프로젝트 입력`, Pending은 `KPI·프로젝트 → 한 프로젝트 이슈`로 이동해 현재 처리 범위를 오해하기 어렵다.
- 제조·품질의 왼쪽 세로 패널 목록은 패널 수가 10면 이상이어도 현재 선택과 완료 상태를 계속 볼 수 있어 가로 목록보다 현장 입력에 적합하다.
- KPI와 프로젝트 표의 정렬·열 순서가 제조·품질·물류·Pending에서 같아 화면별 재학습이 줄었다. 흑백·사각형·1px 경계와 상태값만의 색 사용도 일관적이다.
- 우선 개선점은 프로젝트·구매 목록의 큰 검색/필터·KPI 영역이다. 1280×768에서 실제 프로젝트 표가 첫 화면 아래로 밀려 일상 조회 속도가 떨어진다.
- 프로젝트 상세는 기본 정보 카드가 12개라 탭과 전체 흐름이 첫 화면 아래에 있다. 기본 정보는 1~2행 핵심 요약과 상세 펼치기로 압축하는 편이 좋다.
- Sales는 데이터가 없을 때 큰 12개월 차트가 빈 공간처럼 보이고, 내 업무·알림의 빈 상태도 다음 행동 안내가 부족하다.
- 왼쪽 메뉴는 일상 업무와 관리 메뉴가 길게 한 목록에 있고 일부 한글·영문 표현이 혼재한다. 부서 업무 / 협업 / 관리로 묶고 용어 사전을 적용하면 탐색 부담이 줄어든다.
- 자재 입고는 필터·Excel·교차 업무 이동이 한곳에 밀집해 새 제조·품질·Pending 대시보드보다 시각적으로 무겁다. 자주 쓰는 도착·입고 확정을 앞에 두고 내보내기는 보조 영역으로 내리는 것이 좋다.

## 8. SOP·User manual

1. 왼쪽 메뉴에서 생산관리·자재·품질·물류 중 담당 부서를 누른다. Pending은 3번부터 시작한다.

4. 프로젝트 검색 또는 프로젝트 행을 눌러 한 프로젝트를 연다.
5. 제조·패널 품질검사는 왼쪽 세로 패널 목록에서 처리할 패널을 고른다.
6. 기존과 같은 입력 필드와 하단 저장·판정 버튼으로 업무를 확정한다.
7. 다른 업무로 바꾸려면 상단의 `업무 선택`, 다른 프로젝트로 바꾸려면 `○○ 프로젝트` 버튼을 누른다.

## 11. 개발 기록

### 해결한 업무 문제

한 페이지에서 업무와 프로젝트를 동시에 선택하고 다른 프로젝트의 패널까지 오가던 구조 때문에 KPI의 기준과 현재 입력 대상이 불명확했다. 업무·프로젝트·입력을 순차적으로 분리해 현재 사용자가 무엇을 고르고 무엇을 수정하는지 한 화면에 하나씩만 남겼다.

### 기술적 결정과 검토한 대안

기존 입력 페이지를 다시 작성하지 않고 앞단에 공통 업무 허브와 공통 프로젝트 대시보드를 추가했다. 이 방식은 기존 API·권한·저장 handler를 그대로 유지하면서 화면 진입 구조만 교체해 기능 회귀 위험을 줄인다.

### 시행착오 및 폐기한 접근

프로젝트 행 자체에 `row` 역할을 부여한 버튼은 표 탐색 의미와 버튼 조작 의미가 충돌했다. 표의 행과 실제 버튼을 분리해 행 구조와 키보드 조작을 모두 유지했다. 자재 입력 화면의 기존 `프로젝트` 뒤로가기 문구도 실제 이동 대상에 맞춰 `업무 선택`으로 정리했다.

### 사용자 검수 결과와 남은 항목
