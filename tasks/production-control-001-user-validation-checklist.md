# TASK-PRODUCTION-CONTROL-001 사용자 검수 체크리스트

상태: `사용자 검수 대기 — 마지막 일괄 검수`

고정 검수 환경:

- Frontend: `http://127.0.0.1:42983`
- Backend: `http://127.0.0.1:41166`

검수 역할: System Administrator, 생산계획 담당자

## 자동 검증 완료

- [x] 기존 프로젝트는 `Legacy` 생산계획과 기존 단일 예정일·캘린더를 유지한다.
- [x] 제조·생산계획 양식 사용 시작 전 생성 프로젝트는 `Legacy`로 남는다.
- [x] 두 양식 사용 시작 뒤 생성한 새 프로젝트만 `LinkedV1` snapshot을 가진다.
- [x] 새 프로젝트 생성 후 master 양식을 바꿔도 기존 프로젝트 snapshot은 바뀌지 않는다.
- [x] 생산계획 항목 하나에 여러 제조·구매·자재·품질·물류 source를 연결할 수 있다.
- [x] 제조와 LQC 연결은 제조 단계 불변 identity를 사용한다.
- [x] 프로젝트 생산관리 담당자는 계획 항목·기간·비고·연결만 수정하고 제조 snapshot·자동 실적은 수정할 수 없다.
- [x] 부서 원본 데이터가 없을 때 500 오류 없이 `대기`, 0%로 표시된다.
- [x] FAT 비필수 프로젝트는 FAT를 실적 분모와 유효 연결 요약에서 제외한다.
- [x] desktop 6열 표, 근거 펼침과 계획/실적 가로 막대가 표시된다.
- [x] 모바일 390×844에서 항목 카드와 실제 가로 막대가 표시되고 가로 overflow가 없다.

## 사용자 검수

### 1. 양식 관리

- [ ] System Administrator로 `양식 관리 → 생산계획·Item별 제조 연결`에 들어간다.
- [ ] Item을 선택하고 제조 양식의 항목·조립 구분을 확인한다.
- [ ] 생산계획·연결 탭에서 한 항목에 여러 source가 표시되는지 확인한다.
- [ ] 사용 중 version은 조회 전용이고 `편집용 초안 만들기`로만 변경할 수 있는지 확인한다.
- [ ] “활성화 이후 새 프로젝트부터 적용” 안내가 이해하기 쉬운지 확인한다.

### 2. 신규·기존 프로젝트 경계

- [ ] 기존 프로젝트 생산관리 탭이 이전 화면 그대로인지 확인한다.
- [ ] 연결 양식이 활성화된 Item으로 새 프로젝트를 생성한다.
- [ ] 새 프로젝트 생산관리 탭에 6열 계획 대비 실적표가 표시되는지 확인한다.
- [ ] 이후 master 양식을 변경해도 방금 생성한 프로젝트 항목·연결이 바뀌지 않는지 확인한다.

### 3. 계획 입력

- [ ] 생산계획 담당자로 `생산계획 수정`을 누른다.
- [ ] 항목마다 계획 시작일·종료일·비고를 입력하고 저장한다.
- [ ] 계획 시작일이 종료일보다 늦을 때 이해 가능한 오류가 표시되는지 확인한다.
- [ ] 프로젝트 전용 항목 또는 연결을 수정해도 master 양식과 제조 snapshot이 바뀌지 않는지 확인한다.

### 4. 자동 실적

- [ ] 구매 발주, 자재 입고/IQC, 제조/LQC, OQC·전진검수, 포장·출발·납품을 기존 부서 화면에서 처리한다.
- [ ] 생산관리 탭을 다시 열었을 때 해당 항목 진행률과 실적 시작·종료가 자동 갱신되는지 확인한다.
- [ ] `근거 N건`을 열어 실제 품목·패널별 완료·대기 상태를 추적할 수 있는지 확인한다.
- [ ] 일부 대상만 완료했을 때 100%가 되지 않고 진행 중으로 표시되는지 확인한다.
- [ ] Pending이 열린 대상은 차단 상태로 구분되는지 확인한다.

### 5. 일정표와 모바일

- [ ] 하단 일정표에서 계획 막대와 실적 막대를 구분할 수 있는지 확인한다.
- [ ] 여러 항목의 병행과 지연을 한눈에 파악할 수 있는지 확인한다.
- [ ] 모바일에서 카드 정보와 가로 막대가 잘리지 않고 읽히는지 확인한다.

## 게시 경계

- 대표 repo·`main`·Persistent UAT·실제 provider는 포함하지 않는다.
- push·PR·merge는 포함하지 않는다.
- `main` merge 승인 상태: `0/3`.
