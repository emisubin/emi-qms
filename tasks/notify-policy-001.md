- 일반 업무 배정: 실제 처리 업무 생성 시 PMS 인앱과 Teams 개인 Activity Feed를 함께 사용한다. 참고 알림은 포함하지 않으며 기존 사용자별 일반 업무 알림 선택권을 유지한다.
- 일반 Pending: 우선순위와 무관하게 PMS 인앱·Teams 개인 Activity Feed·메일을 모두 사용한다.
- Teams 공용 채널: 사용하지 않는다. 기존 TeamsChannel delivery 생성·운영 Webhook 경로는 비활성 정책으로 정리한다.

- 프로젝트 생성 채널: 모든 활성 사용자에게 PMS 인앱·Teams 개인 Activity Feed·메일을 모두 발송한다.

- 사용자 결정 근거: 2026-08-11 대화의 `7A`, `8B`, `9A`.

### Round 4 — 일일 요약·예정일·에스컬레이션

- Daily Digest: 평일 `Asia/Seoul` 오전 07:30에 사용자별 한 통을 발송한다. 보낼 내용이 없으면 발송하지 않는다.
- 업무 예정일 원본: 별도 수동 예정일 입력을 기본으로 만들지 않고, 생산계획일·구매품 입고예정일 등 이미 입력된 업무 일정에서 관련 `work_items.due_date`를 자동 계산·동기화한다. 신뢰할 일정 원본이 없는 업무는 `null`로 유지한다.
- 예정일 알림: 단순형만 운영한다. D-1에는 현재 담당자에게 Teams 개인 Activity Feed, 하루 초과 시 현재 담당자에게 Teams 개인 Activity Feed와 메일을 발송한다.
- 확대 에스컬레이션: 기존 L2·L3의 부 담당자·생산관리·영업 확대 발송은 운영하지 않는다.
- 사용자 결정 근거: 2026-08-11 대화의 `10A`, `11A`, `12A`.

### Round 5 — 담당자 fallback·사용자 설정·야간 정책

- 담당자 fallback: 프로젝트에 해당 단계 담당자가 없으면 System Administrator나 영업 담당자까지 내려가지 않고 해당 업무 부서의 활성 부서장에게 fallback한다. 복수 부서장일 때의 업무 owner 정책은 다음 round에서 확정한다.
- 사용자 설정 가능: 일반 자동 업무 배정 Teams, D-1 Teams와 평일 Daily Digest 메일만 사용자가 끌 수 있다.
- 필수 알림: Pending과 프로젝트 생성·납기·상태·납품 완료 등 주요 프로젝트 외부 알림은 사용자가 끌 수 없다.
- 야간 정책: quiet hours를 두지 않는다. 발생 시각과 무관하게 확정된 채널로 즉시 발송한다.
- 사용자 결정 근거: 2026-08-11 대화의 `13B`, `14A`, `15B`.

### Round 6 — 복수 부서장·일괄 처리·재검사

- 복수 부서장 fallback: 같은 부서의 활성 부서장 모두에게 동일 fallback 업무를 표시하고, 한 명이 처리하면 나머지 부서장의 동일 업무도 자동 종료한다. 임의의 한 명을 선택하지 않는다.
- 일괄 업무 알림: 실제 `work_items`는 패널별로 유지하되 한 번의 일괄 처리에서 같은 프로젝트·단계·수신자에게 생기는 인앱 알림은 한 건으로 묶는다. Teams Activity Feed와 PWA push도 같은 묶음 인앱 알림 한 건을 사용한다.
- 재검사 요청: 일반 Pending과 같은 필수 채널 정책을 적용해 PMS 인앱·Teams 개인 Activity Feed·PWA push·메일을 모두 발송한다.
- 재검사 불합격·재조치: 같은 Pending의 재조치 알림에도 PMS 인앱·Teams 개인 Activity Feed·PWA push·메일을 모두 적용한다.
- 사용자 결정 근거: 2026-08-11 대화의 `16A`, `17A`, `18B`와 “재검사도 일반 Pending과 똑같이 처리”.

### Round 7 — 예정일 재계산·fallback·보관

- 일정 변경: 완료되지 않은 업무의 `due_date`는 연결된 생산계획일·구매품 입고예정일 등 원본 일정 변경을 따라 자동 갱신한다.
- 완료 이력: 완료된 업무의 예정일과 이력은 이후 원본 일정 변경으로 수정하지 않는다.
- 일정 fallback: 정확히 연결되는 일정 원본이 없으면 `due_date=null`로 유지하고 기한 알림을 만들지 않는다. 프로젝트 전체 납기일이나 부서장 수동 입력으로 임의 대체하지 않는다.
- 인앱 보관: 알림을 기간 기준으로 자동 숨김·삭제하지 않고 계속 보관한다. 읽음 상태와 조회 필터를 사용하며 audit 근거를 유지한다.
- 사용자 결정 근거: 2026-08-11 대화의 `19A`, `20A`, `21A`.
