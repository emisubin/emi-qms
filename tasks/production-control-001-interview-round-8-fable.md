## 1. 해결할 문제와 기대 결과

- 지금은 생산계획 항목마다 단일 예정일과 비고만 입력하고, 각 부서가 일을 끝내도 생산관리 담당자가 부서 화면을 오가며 진행 상황을 직접 확인해 옮겨야 합니다.
- 이 기능이 완성되면, 새 양식으로 생성되는 프로젝트의 상세 생산관리 탭 한곳에서 계획 항목별 **계획 기간(담당자 입력)**과 **실적 기간(부서 실데이터에서 자동 계산)**, 진행률, 지연·차단 상태와 구매품목·패널별 근거를 확인하고, 같은 정보를 계획/실적 가로 막대 일정으로 비교할 수 있습니다.

## 2. 적용 대상: 기존 프로젝트와 새 프로젝트 (Round 7 확정)

1. **기존 프로젝트는 지금 화면을 그대로 유지합니다.** 단일 예정일 + 체크 표시 캘린더 화면과 생성 당시 양식을 계속 사용하며, 새 계획·실적 표와 가로 막대 일정은 적용하지 않습니다.
2. **새 양식 version으로 생성되는 프로젝트부터** 계획·실적 표, 가로 막대 일정과 자동 실적 연결을 사용합니다.
3. 이 결정에 따라 기존 프로젝트를 대상으로 했던 다음 두 규칙은 **적용 대상이 없어져 이번 범위에서 제외**됩니다.
   - 기존 단일 예정일을 계획 시작일·종료일로 복사하는 이전 작업(Round 2 결정 4)
   - 과거 제조·검사 기록을 이름이 정확히 일치할 때 연결하는 규칙(Round 3 결정 3)
4. 필수 항목의 계획 시작·종료 입력으로 생산계획 단계를 완료 판정하는 규칙(Round 2 결정 5)도 새 양식 프로젝트에만 적용하고, 기존 프로젝트는 기존 판정 방식을 유지합니다.

## 3. 양식 관리와 동적 연결 (Round 5·6 확정)

1. 생산계획 항목과 제조 항목은 고정 목록이 아니라 **관리자가 자유롭게 구성하는 Item별 양식**입니다. 앞으로 항목을 전면 교체해도 코드 수정 없이 화면에서 다시 구성합니다.
2. 기존 **양식 관리 화면에 "생산계획" 영역을 추가**하고, 기존 생산관리 설정 화면의 단계 편집 기능을 이 영역으로 통합합니다. 초안 작성 → 사용 시작 → 보관의 기존 버전 관리 방식을 재사용합니다.
3. **제조 항목도 Item별 양식으로 확장**하고, 프로젝트 생성 시 생산계획 항목·제조 항목·연결 관계를 한 세트로 프로젝트에 복사(snapshot)합니다. 이후 패널 제조 시작은 프로젝트에 복사된 단계를 사용합니다.
4. 각 항목에는 버전이 바뀌어도 유지되는 **고유 이름표(immutable identity)**를 시스템이 자동 부여합니다. 이름·순서를 바꿔도 연결이 유지되고, 항목을 삭제하면 그 연결만 `연결 안 됨`으로 표시되어 재연결을 안내합니다.
5. 생산계획 항목 하나는 **여러 실적 대상**에 연결할 수 있습니다. 제조는 관리자가 구성한 제조 항목 목록에서, **구매·자재·품질·물류는 시스템이 이미 확정 처리하는 고정 사건 목록**(예: 발주 완료, 전체 입고 확정, IQC 합격, LQC 합격, OQC 합격, 전진검수 합격, FAT 합격, 포장 완료, 출발 처리, 납품 완료)에서 선택합니다(Round 7 확정).
6. 양식이 바뀌어도 이미 생성된 프로젝트는 생성 당시 복사본을 계속 사용하고, 새 버전은 게시 이후 새로 생성되는 프로젝트부터 적용됩니다.
7. 프로젝트 안에서도 프로젝트 전용 계획 항목 추가와 실적 연결 수정이 가능하며, 이 변경은 양식 원본이 아닌 해당 프로젝트 복사본에만 기록됩니다.

## 4. 권한 (Round 6 확정)

- 시스템 관리자가 사람 단위로 지정하는 기존 양식 관리자 방식을 확장합니다. **제조 양식 관리자**는 제조 항목을, **생산계획 양식 관리자와 시스템 관리자**는 생산계획 항목·실적 연결을 관리합니다.
- 프로젝트 안의 계획 기간·항목·연결 수정은 지금처럼 **생산관리 정·부 담당자**가 합니다.
- 구매·자재·제조·품질·물류 담당자는 기존 부서 화면에서만 입력하고, 생산관리 실적을 직접 고칠 수 없습니다. 다른 부서는 조회 전용이며, 시스템 관리자의 업무 입력 금지 불변조건은 유지됩니다.

## 5. 계획·실적 데이터 규칙 (Round 2·3 확정, 새 양식 프로젝트 대상)

1. 각 계획 항목은 계획 시작일·종료일(담당자 입력, 같은 날 허용, 역전 시 저장 불가)과 실적 시작일·종료일(자동 계산, 직접 수정 불가)을 가집니다.
2. 자동 실적은 생산관리 탭을 조회할 때 최신 부서 원본 데이터에서 항상 같은 결과가 나오도록 계산합니다.
3. 실적 시작은 연결 대상에서 최초 유효 업무 사실이 발생한 시각, 실적 종료는 모든 활성 대상이 완료된 마지막 시각입니다. 일부만 완료되면 실적 시작과 `완료 수/전체 수`를 표시하고 종료일은 비워 둡니다.
4. 실적 날짜는 담당자가 적은 실제 업무 날짜(도착일·출발일 등)를 우선하고, 별도 업무 날짜가 없는 업무만 시스템 확정 시각의 한국 날짜를 사용합니다.
5. 구매·자재 완료는 기존 자재 화면의 담당자 확정 행위를 기준으로 하고 수량은 근거로만 표시합니다. 재검사가 있으면 실적 기간은 최초 검사 시작부터 최종 합격까지입니다.
6. 계획 수정은 현재 값 + 기존 변경 기록 방식을 유지하고, 최초 기준 계획 비교 화면은 이번 범위에서 제외합니다.

## 6. 화면 구성 (Round 4 확정)

1. PC 표는 `항목명 / 필수 / 계획 기간 / 실적 기간 / 진행률 / 일정 상태` 6칸을 기본 표시하고, 비고와 구매품목·패널별 근거는 행 펼침(한 번에 한 항목)에서 확인합니다.
2. 가로 막대 일정은 하루 단위 고정 축 + 항목명 열 고정 + 가로 스크롤이며, 열면 오늘 위치로 자동 이동합니다. 계획 막대(외곽선/패턴)와 실적 막대(상태 의미색 채움)를 항목별로 비교하고, 오늘 기준선·주말·공휴일과 지연 일수 텍스트를 표시합니다.
3. 390px 좁은 화면은 항목별 카드(상태·계획/실적 기간·지연 텍스트 + 축약된 두 줄 막대)로 표시하고 가로 스크롤을 쓰지 않습니다.
4. 일정표는 계획 항목 단위 막대만 유지하고, 대상별 근거는 펼침 표에서만 보여줍니다.
5. 접근성은 표를 공식 대체 수단으로 유지하고, 각 막대에 텍스트 설명을 붙이며, 상태는 색 + 채움 패턴 + 텍스트를 함께 사용합니다. 흑백 와이어프레임 기본 디자인을 유지합니다.
