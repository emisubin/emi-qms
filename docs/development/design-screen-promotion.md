# 디자인 화면의 제품 반영

기존 청주 UI 재사용은 [Frontend 지침](../../frontend/AGENTS.md)을 따른다. 이 문서는 별도 디자인 실험을 실제 제품에 옮기는 경우에만 사용한다.

## 보존할 계약

승인된 화면·상태·공용 component 소비자·asset·검증 범위를 해당 Task/change에 정리한다. 기능·권한·접근성·데이터 흐름을 보존하고 실험 branch 전체를 제품에 덮어쓰지 않는다.

같은 화면에서 디자인과 최신 기능 코드가 다르면 사용자 계약에 맞게 조정한다. 구현 방법 차이만으로 재승인을 요구하지 않으며, 승인된 시각 결과나 업무·권한 의미가 달라지는 미결정만 질문한다.

## 실행

현재 기준선과 WIP·runtime source를 확인한다. 물리 격리가 필요하면 bounded worktree를 사용하고, 고정된 과거 포트를 항상 새로 열지 않는다. 실제 owner·기동·복구는 해당 환경 SOP에서 확인한다.

승격할 화면·공용 소비자·시험 범위를 분리해 최신 대상 코드에 반영하고, [검증표](validation-matrix.md)의 영향 테스트와 실제 화면 비교를 한다. 독립 검토는 [완료 정책](../12-task-completion-policy.md)의 위험 기준을 사용한다. 같은 suite를 실험·parent·reviewer가 이유 없이 반복하지 않는다.

제품 반영 범위·대상이 승인돼 있으면 같은 승인을 반복하지 않는다. 사용자 검수·공유 runtime handover·원격 병합/배포 경계는 [Root](../../AGENTS.md)를 따른다. 품질 GO나 local commit은 게시 승인이 아니다.

## 실패와 이력

검수에서 실패한 화면·상태는 기존 Task change로 보정한다. 승인 조건이 실질적으로 달라지면 그 차이만 확정한다. rollback도 대상·데이터 호환성·영향을 확인하고 다른 화면·DB·runtime으로 범위를 넓히지 않는다.

이전 5176→5174 강제 절차와 당시 승격 상태는 [보존본](../archive/harness-v1-2026-09-09/design-screen-promotion.md.snapshot)에 있다. 그 주소·과거 승인·미완료 표기를 새 작업의 현재 상태로 재사용하지 않는다.
