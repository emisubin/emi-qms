2. **양식 관리 화면**: 검사 양식 5종과 제조 작업 단계 양식을 "초안 작성 → 사용 시작 → 보관" 방식으로 버전 관리하고, 시스템 관리자가 부서별 양식 관리자(예: 품질 부서장, 제조 부서장)를 지정하는 화면입니다. 제조 단계 양식은 현재 **회사 공용 1개**이며, 각 패널의 제조를 "시작"하는 순간의 사용 중 양식이 그 패널에 복사됩니다.

### 질문 1 — 생산계획 항목과 실적 연결을 관리할 화면의 위치

**왜 필요한가요:** 새로 만들 "제조 항목·생산계획 항목·실적 연결 구성" 기능을 어느 화면에 둘지에 따라 화면 구조, 권한 방식, 변경 이력 방식이 달라집니다.
**답이 바꾸는 범위:** 관리 화면 설계 전체, 기존 생산관리 설정 화면의 처리 방향.

- **A. 기존 "양식 관리" 화면에 "생산계획" 영역을 추가한다.** Item별 생산계획 항목과 실적 연결을 제조·검사 양식과 같은 방식(초안 → 사용 시작 → 보관, 새 프로젝트부터 적용)으로 관리하고, 기존 생산관리 설정 화면의 단계 편집 기능은 이 새 영역으로 통합한다.
  - 장점: 제조 항목과 생산계획 항목을 한 화면에서 구성(사용자가 말씀하신 형태)하고, 이미 있는 버전 관리·관리자 지정·변경 기록을 그대로 재사용합니다. 사용 중인 양식을 실수로 고칠 수 없습니다.
  - 단점: 기존 생산관리 설정 화면과 역할이 겹쳐 정리 작업이 필요합니다.
- **B. 기존 생산관리 설정 화면을 확장해 연결 구성까지 넣는다.**
  - 장점: 생산관리 담당자에게 익숙한 위치입니다.
  - 단점: 이 화면에는 버전·"사용 시작" 개념이 없어 새 프로젝트부터 적용하는 규칙과 변경 이력을 처음부터 다시 만들어야 하고, 제조 항목 관리와 화면이 갈라집니다.

**권장: A.** 이미 검증된 버전 관리 방식을 재사용하는 것이 안전하고, "관리자와 부서 팀장이 한 곳에서 구성한다"는 말씀과도 맞습니다.

### 질문 2 — 제조 항목을 Item별로 나눌지, 회사 공용으로 둘지

**왜 필요한가요:** "프로젝트 생성 시 선택된 Item 양식의 제조 항목을 자동 생성한다"고 하셨는데, 지금 제조 단계 양식은 Item 구분 없이 회사 공용 1개이고, 프로젝트 생성이 아니라 각 패널의 제조 시작 시점에 복사됩니다. 시점과 단위가 달라 확정이 필요합니다.
**답이 바꾸는 범위:** 제조 양식 구조, 프로젝트 생성 처리, 패널 제조 시작 처리, 연결 안정성.

- **A. 제조 항목도 Item별 양식으로 확장하고, 프로젝트 생성 시 프로젝트에 복사한다.** 이후 패널 제조 시작은 프로젝트에 복사된 단계를 사용한다.
  - 장점: Item마다 제조 방식이 다르면 정확하게 표현됩니다. 한 프로젝트 안에서 계획 항목·제조 단계·연결이 한 세트로 고정되어 실적 집계가 단순하고 안정적입니다.
  - 단점: 기존 "제조 시작 시점 복사" 방식을 바꾸는 큰 변경입니다. 이미 진행 중인 패널은 기존 방식 기록을 그대로 보존해야 합니다.
- **B. 제조 양식은 회사 공용으로 유지한다.** 프로젝트 생성 시에는 생산계획 항목과 연결만 복사하고, 제조 단계는 지금처럼 패널 제조 시작 때 복사한다.
  - 장점: 기존 제조 흐름을 건드리지 않아 변경 범위가 작습니다.
  - 단점: 프로젝트 진행 중에 제조 양식이 바뀌면 같은 프로젝트 안에서 패널마다 단계 구성이 달라질 수 있어, 연결·집계 화면이 복잡해집니다.

**권장: A.** 말씀하신 "Item 양식에서 제조 항목·생산계획 항목·연결을 함께 자동 생성"하는 그림과 일치하는 것은 A입니다. 다만 변경 범위가 커지므로, Item별 구분이 실제 업무에서 필요 없다면 B도 가능합니다.

### 질문 3 — 항목이 교체되어도 연결이 살아남는 방법

**왜 필요한가요:** 생산계획 항목과 제조 단계를 앞으로 전면 교체·수정하실 예정이므로, 이름이나 순서가 바뀌어도 "이 계획 항목은 이 제조 단계들과 연결"이라는 관계를 지킬 방법을 정해야 합니다.
**답이 바꾸는 범위:** 연결 저장 방식, 새 버전 게시 때 관리자가 해야 할 일의 양.

- **A. 각 항목에 버전이 바뀌어도 유지되는 고유 이름표를 시스템이 자동 부여한다.** 새 버전을 만들 때 기존 항목을 복제하면 이름표가 유지되어 이름·순서를 바꿔도 연결이 그대로 따라간다. 항목을 삭제하면 그 항목에 걸린 연결만 "연결 안 됨"으로 표시되어 재연결을 안내한다.
  - 장점: 게시 때마다 연결을 다시 만들 필요가 없어 운영 부담이 적고, 누락이 생기면 화면에 바로 드러납니다.
  - 단점: "항목 수정"과 "항목 삭제 후 새로 추가"의 차이를 관리자가 이해해야 합니다(화면 안내로 보완).
- **B. 연결은 특정 버전의 항목에 직접 걸고, 새 버전을 게시할 때마다 연결을 전부 다시 확인·연결한다.**
  - 장점: 매번 명시적으로 확인하므로 규칙이 단순합니다.
  - 단점: 게시할 때마다 수작업이 반복되고, 빠뜨리면 자동 실적이 끊깁니다.

**권장: A.**

또 한 가지 함께 확인드립니다. 구매·자재·품질·물류 쪽 연결 대상은 항목을 자유 구성하는 것이 아니라, 시스템이 이미 확정 처리하는 사건 목록에서 고르는 방식을 권장합니다 — 예: 발주 완료, 전체 입고 확정, IQC 합격, LQC 합격, OQC 합격, 전진검수 합격, FAT 합격, 포장 완료, 출발 처리, 납품 완료. 즉 **제조 단계만 동적 목록이고 나머지 부서는 고정 사건 목록에서 선택**하는 방식입니다. 이렇게 이해한 것이 맞는지 확인 부탁드립니다. (다르면 알려 주세요.)

### 질문 4 — 누가 무엇을 편집할 수 있는지

**왜 필요한가요:** "관리자와 각 부서 팀장"이라고 하셨는데, 시스템에는 별도 "팀장" 역할이 없고, 기존 양식 관리는 시스템 관리자가 부서별 "양식 관리자"를 사람 단위로 지정하는 방식을 사용합니다.
**답이 바꾸는 범위:** 양식 관리 화면의 권한 판정, 프로젝트 안 수정 권한.

- **A. 기존 지정 방식을 그대로 확장한다.** 시스템 관리자가 "생산계획" 양식 관리자(예: 생산관리 부서장)를 지정한다. 제조 항목 편집은 기존 제조 양식 관리자가 담당한다. 생산계획 항목과 실적 연결 구성은 생산계획 양식 관리자와 시스템 관리자가 담당한다. 프로젝트 안에서의 계획 기간·항목·연결 수정은 지금처럼 생산관리 정·부 담당자가 한다.
  - 장점: 이미 운영 중인 지정·해제·감사 방식을 재사용하고, 부서별 책임이 명확합니다.
- **B. 항목 구성은 부서 양식 관리자가 하되, 부서 간 연결(생산계획 ↔ 제조·품질 등) 구성은 시스템 관리자 전용으로 둔다.**
  - 장점: 부서 간 영향이 있는 연결을 한 사람이 통제합니다.
  - 단점: 양식을 바꿀 때마다 시스템 관리자를 거쳐야 해서 느려집니다.

**권장: A.** 연결이 잘못되어도 부서 원본 데이터는 바뀌지 않고 표시만 달라지므로, 통제보다 운영 속도가 중요하다고 판단합니다.

### 질문 5 — 기존 프로젝트와 과거 기록을 어떻게 보여줄지

**왜 필요한가요:** Round 3에서 "이름이 정확히 일치할 때만 과거 기록을 연결"이라고 답하셨지만, 항목을 전면 교체하시면 기존 이름과 새 이름이 달라 대부분 자동 연결되지 않습니다. 기존 프로젝트가 새 화면을 어떻게 쓰는지 확정이 필요합니다.
**답이 바꾸는 범위:** 기존 데이터 이전 규칙, 기존 프로젝트의 화면 동작.

- **A. 기존 프로젝트도 새 계획·실적 표와 가로 막대 일정 화면을 사용하되, 자동 연결은 하지 않는다.** 기존 항목은 "연결 안 됨"으로 표시되고 계획 기간은 입력할 수 있다. 담당자가 프로젝트 안 연결 수정으로 직접 연결한 항목부터 자동 실적이 표시된다. 기존 단일 예정일은 Round 2 결정대로 계획 시작일·종료일 같은 날짜로 복사하고 원본을 보존한다.
  - 장점: 잘못된 자동 연결이 없고, 필요한 프로젝트만 골라서 손보면 됩니다. 화면은 하나로 유지됩니다.
- **B. 기존 프로젝트는 지금 화면(단일 예정일 + 체크 캘린더)을 유지하고, 새 프로젝트만 새 화면을 쓴다.**
  - 장점: 기존 프로젝트를 전혀 건드리지 않습니다.
  - 단점: 두 화면을 계속 유지보수해야 하고, 진행 중인 프로젝트는 새 기능을 쓸 수 없습니다.
- **C. 기존 항목명을 새 항목과 자동으로 짝지어 연결을 시도한다.**
  - 단점: 전면 교체 상황에서는 잘못 연결될 위험이 커서, "임의 연결은 하지 않는다"는 Round 3 답변과 어긋납니다.

**권장: A.**
