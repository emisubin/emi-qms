# <기능 — 사용자 문제와 기대 결과>

기획 요청 또는 복잡한 구현에 필요한 깊이로 작성한다. 작은 수정에 별도 전문을 요구하지 않는다.

## 범위와 결정

- 사용자 문제·기대 결과·요청 출처:
- 현재 동작·관련 Task/ADR:
- 포함/제외 범위와 보존할 업무·권한·데이터 계약:
- 실제로 남은 결정, 선택지·권장안과 영향:

## 구현 방향

인터페이스·데이터 흐름·실패 경계와 순서를 설명한다. 독립적으로 검증할 사용자 결과로 작업을 나누며 준비/설정/문서는 해당 결과에 포함한다. 전체 구현 코드를 기획서에 복제하지 않는다.

## 완료와 검증

사용자가 확인할 결과와 성공·거부·실패·경계의 검증을 연결한다. 필요한 운영 변경·복구와 승인 대상은 구체화한다. 실제 검증·사용자 검수·게시 상태는 구현 후 [현재 Task](task-template.md)에 기록한다.

내용 검토는 사용자 가치·우선순위·누락·과도한 범위·대안과 구현 가능성을 함께 본다. 위험에 필요한 독립 검토는 [완료 정책](../../docs/12-task-completion-policy.md)을 따른다. 기획만 요청받았다면 구현하지 않으며, 이미 명확히 승인된 구현에 기획/리뷰 해결사항의 중복 승인 단계를 추가하지 않는다. 과거 승인본을 현재 기획으로 덮어쓰지 않는다.
