# DESIGN-000 Change 003 — PC UX/UI 사용자 관점 평가서

## 1. 문서 목적

이 문서는 `DESIGN-000 Change 003` 구현 이후의 PC 화면을 실제 업무 사용자의 관점에서 평가한 결과다.

평가의 목적은 기능 존재 여부를 다시 확인하는 것이 아니라 다음을 구분하는 데 있다.

1. 현재 화면에서 잘 작동하는 구조와 반드시 보존해야 할 장점
2. 사용자가 업무를 처리할 때 실제로 느끼는 불편
3. 기능은 유지하면서 배치·표현·조작 방식만 개선해야 하는 부분
4. 즉시 수정할 문제와 장기적으로 정리할 문제의 우선순위

모바일은 사용자 요청에 따라 평가 대상에서 제외했다.

## 3. 종합 평가

### 종합 점수: 6.8 / 10

현재 PC 버전은 실제 업무를 처리할 수 있을 정도로 기능과 정보가 충분하다. 특히 최근 개편한 제조·품질·Pending의 `KPI → 프로젝트 목록 → 단일 프로젝트 입력` 구조는 이전보다 명확하며, 여러 프로젝트와 패널이 한 화면에 섞이던 문제를 상당 부분 해소했다.

그러나 전체 제품 수준에서는 아직 “사용자가 화면을 해석하면서 업무해야 하는 시스템”에 가깝다. 사용자가 원하는 것은 대부분 실제 목록, 처리 대상, 입력 버튼인데 일부 화면에서는 큰 KPI, 필터, 요약, 내보내기 기능이 그보다 먼저 나온다. 이 때문에 기능은 있어도 업무 시작 속도가 느리고, 페이지마다 입력 방식이 달라 신규 사용자가 계속 화면을 학습해야 한다.

핵심 문제는 기능 부족이 아니다. 다음 세 가지가 현재 PC UX의 가장 큰 문제다.

1. **실제 업무 목록이 첫 화면 아래로 밀리는 정보 우선순위 문제**
2. **조회 전용·일괄 선택·현재 처리 대상이 명확하지 않은 조작 의미 문제**
3. **같은 종류의 화면인데도 헤더·뒤로가기·필터·입력·저장 방식이 다른 일관성 문제**

## 4. 반드시 보존해야 할 장점

### 4.1 상태 색상을 제한하고 문구를 함께 표시하는 방식

흑백 와이어프레임을 기본으로 유지하고 상태에만 색을 사용하는 방향은 적절하다. 상태를 색만으로 구분하지 않고 `대기`, `진행 중`, `Pending`, `완료` 같은 문구를 같이 표시해 색각 이상 사용자와 익숙하지 않은 사용자도 상태를 이해할 수 있다.

이 규칙은 앞으로도 유지해야 한다. 장식 목적으로 색을 다시 늘리면 업무 상태의 중요도가 약해진다.

### 4.2 `업무 선택 → KPI·프로젝트 → 단일 프로젝트 입력` 구조

생산관리·자재·품질·물류에서 업무를 먼저 선택하고, 해당 업무의 프로젝트 목록을 거쳐 한 프로젝트에 들어가는 구조는 정보 경계를 분명하게 만든다.

사용자는 다음을 쉽게 이해할 수 있다.

- 지금 어떤 업무를 선택했는가
- 어떤 프로젝트를 처리하려는가
- 현재 입력 내용이 어느 프로젝트에 저장되는가

이 3단계 구조는 앞으로 다른 부서 업무를 추가할 때도 공통 진입 구조로 유지하는 것이 좋다.

### 4.3 제조·품질의 세로 패널 목록

패널이 10개 이상일 때 가로 칩보다 세로 목록이 훨씬 안정적이다.

- 한 화면에서 더 많은 패널을 볼 수 있다.
- 현재 선택한 패널과 완료 상태를 계속 확인할 수 있다.
- 입력 영역을 바꿔도 패널 목록의 위치가 유지된다.
- 긴 패널명이나 상태 문구를 표시할 공간이 충분하다.

패널 단위 제조·품질 업무의 기본 탐색 방식으로 보존해야 한다.

### 4.4 제조·품질·Pending의 첫 화면 밀도

이 세 화면은 현재 다른 목록 화면이 따라야 할 좋은 기준이다.

1280×720 기준으로 제조·품질·Pending은 KPI가 약 220px 지점에 시작하고 프로젝트 표가 약 421px 지점에 시작한다. 첫 화면 안에서 KPI와 실제 업무 행을 동시에 확인할 수 있다.

사용자는 화면에 들어온 뒤 별도 스크롤 없이 다음을 수행할 수 있다.

- 전체 현황 확인
- 처리 프로젝트 식별
- 프로젝트 선택

### 4.5 고정 저장 바

생산관리와 제조 등 긴 입력 화면에서 저장·취소 영역이 하단에 고정되는 것은 유용하다.

- 긴 화면을 다시 맨 아래까지 내려갈 필요가 없다.
- 현재 변경사항을 저장할 수 있는지 계속 확인할 수 있다.
- 입력 후 저장을 잊을 가능성을 줄인다.

단, 화면마다 서로 다른 저장 바가 여러 개 생기지 않도록 저장 책임을 분명하게 유지해야 한다.

### 4.6 프로젝트 상세의 통합 조회 능력

프로젝트 상세에 생산관리·설계·구매·제조·품질·물류·영업 데이터가 함께 있는 구조는 협업 관점에서 강점이다. 다른 부서의 전체 진행 상황을 별도 메뉴로 이동하지 않고 확인할 수 있다.

내용을 삭제하기보다 상단 요약을 압축하고 탭 접근성을 개선하는 것이 맞다.

### 4.7 프로젝트 단위 내 업무·알림 구성

내 업무와 알림을 프로젝트 단위로 묶고 상세 내용을 열로 표시하는 방향은 좋다.

사용자는 동일 프로젝트에서 발생한 여러 업무를 함께 이해할 수 있고, 프로젝트명을 반복해서 읽는 부담도 줄어든다. 이 구조는 데이터가 충분히 있을 때 특히 효과적이다.

### 4.8 가로 스크롤을 만들지 않은 PC 적응

검수한 주요 화면은 1280px 폭에서 가로 넘침이 발생하지 않았다. 표와 입력 화면이 많음에도 기본 PC 해상도에서 좌우 스크롤을 강요하지 않는 점은 좋다.

## 5. 공통 단점

### 5.1 실제 업무보다 요약·필터·내보내기가 먼저 보인다

프로젝트, 구매, 자재 화면은 사용자가 가장 자주 찾는 실제 목록보다 KPI·필터·내보내기 도구가 먼저 나온다.

측정 결과:

| 화면 | 실제 목록 시작 위치 | 720px 첫 화면 노출 |
| --- | ---: | --- |
| 프로젝트 | 약 791px | 첫 행이 보이지 않음 |
| 구매 | 약 738px | 첫 행이 거의 보이지 않음 |
| 자재 입고 | 약 705px | 목록의 시작 부분만 보임 |
| 제조 | 약 421px | 첫 행이 보임 |
| 품질 | 약 421px | 첫 행이 보임 |
| Pending | 약 421px | 첫 행이 보임 |

사용자는 프로젝트를 찾거나 업무를 처리하려고 화면에 들어온다. 첫 번째 행동이 스크롤이 되면 목록 중심 업무 화면의 우선순위가 잘못된 것이다.

### 5.2 프로젝트 상세 탭이 첫 화면 아래에 있다

프로젝트 상세의 탭은 약 886px부터 시작한다. 사용자가 제조·품질·물류 상태를 확인하려고 프로젝트를 열어도 기본 정보 카드와 병목 영역을 먼저 지나야 한다.

기본 정보는 중요하지만 매번 모두 같은 크기로 보여 줄 필요는 없다. 현재 구조는 “정보가 없어서 불편한 문제”가 아니라 “정보가 많아서 업무가 밀리는 문제”다.

### 5.3 조회 전용 표시가 일관되지 않다

모든 부서가 다른 부서 메뉴를 조회할 수 있게 한 정책은 좋다. 하지만 조회 전용 표시가 화면마다 다르다.

- 일부 자재 화면은 조회 전용 안내를 표시한다.
- 제조·품질은 버튼이 비활성화되지만 화면 상단 안내가 없는 경우가 있다.
- 사용자는 권한이 없는 것인지, 선행 조건이 부족한 것인지, 시스템 오류인지 구분하기 어렵다.

모든 타 부서 화면에서 동일한 조회 전용 배너를 사용해야 한다.

### 5.4 체크박스와 현재 항목 선택의 의미가 겹친다

제조·품질의 세로 패널 목록에는 체크박스와 패널 선택 동작이 함께 있다.

- 체크박스: Excel 내보내기 또는 일괄 처리 대상
- 패널 행 또는 칩 클릭: 현재 입력할 패널 선택

두 동작이 가까이 있으므로 사용자는 체크박스를 눌러야 패널 입력이 열리는지, 패널을 누르면 일괄 선택도 되는지 혼동할 수 있다.

일괄 처리 모드를 별도로 켰을 때만 체크박스를 보이거나, 체크박스 옆에 목적을 명시해야 한다.

### 5.5 뒤로가기와 경로 표시가 화면마다 다르다

현재 뒤로가기 표현은 다음처럼 섞여 있다.

- 업무 선택
- 제조 프로젝트
- LQC 프로젝트
- 프로젝트 목록
- 목록
- 화살표 아이콘만 표시

사용자는 뒤로 가면 정확히 어디로 이동하는지 매번 확인해야 한다.

`부서 > 업무 > 프로젝트 > 패널` 형식의 breadcrumb와 `프로젝트 목록으로` 같은 명시적 버튼을 공통으로 사용해야 한다.

### 5.6 빈 상태가 다음 행동을 안내하지 않는다

내 업무, 알림, 일부 물류 화면에서 데이터가 없을 때 한 줄 설명만 남는다.

사용자는 다음을 판단하기 어렵다.

- 정말 배정된 업무가 없는가
- 필터 때문에 보이지 않는가
- 갱신이 필요한가
- 어느 화면에서 업무를 생성해야 하는가

빈 상태는 단순히 비어 있음을 보여 주는 것이 아니라 다음 행동을 안내해야 한다.

### 5.7 한국어 업무 시스템 안에 장식성 영문이 혼재한다

`PROJECT OPERATIONS`, `SHOP FLOOR`, `ISSUE CONTROL` 같은 영문 eyebrow가 한국어 업무명 위에 반복된다. 디자인 장식으로는 보이지만 정보 전달에는 기여하지 않고 화면의 시각적 소음을 늘린다.

약어와 고유 업무 용어를 제외하면 한국어를 우선하는 것이 좋다.

### 5.8 일상 업무 화면에서 Excel 기능의 시각적 비중이 크다

선택 내보내기는 필요한 기능이다. 그러나 검색·필터·업무 버튼과 같은 수준으로 노출되면 사용자는 무엇이 기본 행동인지 판단하기 어렵다.

내보내기를 삭제할 필요는 없지만 `추가 기능` 또는 보조 도구 영역으로 내려야 한다.

## 6. 화면별 상세 평가

### 6.1 공통 좌측 메뉴

#### 장점

- 관리자 기준 주요 메뉴가 720px 높이 안에 표시된다.
- 현재 선택 메뉴를 검은색으로 명확히 강조한다.
- 모든 부서가 전체 메뉴를 볼 수 있어 부서 간 진행 상황 조회가 가능하다.

#### 단점

- 일상 업무와 관리자 기능이 긴 단일 목록에 섞여 있다.
- 사용 빈도와 중요도가 다른 메뉴가 같은 수준으로 표시된다.
- 메뉴 수가 더 늘어나면 현재 구조는 빠르게 한계에 도달한다.

#### 수정 권장

메뉴를 다음 네 그룹으로 정리한다.

1. 내 업무: 홈, 내 업무, 알림, Pending
2. 부서 업무: 현재 로그인 부서의 주요 업무
3. 공통 조회: 프로젝트와 다른 부서 업무
4. 관리: 양식, 사용자, 관리자 기능

다른 부서 메뉴는 숨기지 않되 `공통 조회` 아래에 두고 조회 전용임을 표시한다.

### 6.2 홈

#### 장점

- 로그인 부서에 따라 핵심 KPI가 달라진다.
- 공통 내 업무·Pending·알림·공지사항이 함께 제공된다.
- 생산관리 홈은 부서 KPI와 일상 업무의 균형이 비교적 좋다.

#### 단점

- 영업 홈에서 1년 매출 그래프가 큰 공간을 사용한다.
- 영업 사용자의 내 업무·Pending·알림은 약 721px부터 시작해 첫 화면에서 보이지 않는다.
- 사용자는 그래프보다 오늘 해야 할 업무와 긴급 Pending을 먼저 확인할 가능성이 높다.

#### 수정 권장

- 그래프 위에 `오늘 내 업무 / 긴급 Pending / 새 알림` 한 줄 요약을 배치한다.
- 그래프 높이를 축소하거나 접기를 제공한다.
- 공지사항은 현재처럼 하단에 유지한다.
- 데이터가 모두 0일 때는 빈 그래프만 보여 주지 말고 `매출 또는 목표 데이터가 없습니다`와 입력 경로를 안내한다.

### 6.3 프로젝트 목록

#### 장점

- 검색, 기간, 상태, KPI, 내보내기를 한 화면에서 사용할 수 있다.
- 프로젝트 행 전체를 선택할 수 있고 체크박스 클릭과 행 이동이 충돌하지 않는다.
- 키보드로 행을 열 수 있는 구조가 반영돼 있다.

#### 단점

- 문서 높이가 약 1,474px이며 실제 표가 약 791px에서 시작한다.
- 1280×720에서는 프로젝트 한 행도 보이지 않는다.
- 검색 입력, 기간 필터, KPI 6개, 탭, Excel 선택 도구가 모두 목록 앞에 누적된다.

#### 수정 권장

- KPI를 한 줄의 낮은 카드로 압축한다.
- 기간 필터는 기본 접힘으로 제공한다.
- 상태 탭과 검색을 한 줄에 배치한다.
- Excel 선택 도구는 표에서 항목을 선택했을 때만 나타나게 한다.
- 첫 화면에 최소 2~3개 프로젝트 행이 보이도록 한다.

### 6.4 프로젝트 상세

#### 장점

- 한 프로젝트에 연결된 모든 부서 데이터를 조회할 수 있다.
- 기본 정보, 진행률, 병목, 부서 탭의 범위가 충분하다.
- 부서별로 패널 목록과 현재 진행 상태를 볼 수 있다.

#### 단점

- 탭이 약 886px 아래에서 시작한다.
- 기본 정보 11~12개가 같은 크기의 카드로 반복된다.
- 생산관리와 설계 탭은 전체 문서 높이가 각각 약 2,427px, 2,738px에 달한다.
- 사용자가 특정 부서 데이터를 확인하려면 항상 같은 상단 정보를 지나야 한다.

#### 수정 권장

- 기본 정보는 프로젝트명, 고객사, Item, Code, 납기일, 전체 진행률만 1~2행으로 표시한다.
- 나머지 기본 정보는 `상세 정보 펼치기` 안으로 이동한다.
- 부서 탭은 상단에 고정한다.
- 병목은 큰 카드 대신 한 줄 요약으로 줄인다.
- 마지막으로 확인한 탭을 프로젝트별 또는 사용자별로 기억하는 방식을 검토한다.

### 6.5 생산관리

#### 장점

- 생산계획과 제조 투입을 업무 선택 단계에서 분리했다.
- 생산관리 목록은 KPI와 첫 프로젝트 행이 첫 화면에 들어온다.
- 저장 바가 하단에 고정되어 긴 입력 중에도 저장 위치를 잃지 않는다.

#### 단점

- 계획 입력 화면 높이가 약 2,626px이다.
- 입력 요소 41개와 담당자 카드 11개가 한 번에 펼쳐진다.
- 사용자는 무엇부터 입력해야 하는지 판단하기 어렵다.
- 필수값과 선택값의 우선순위가 충분히 구분되지 않는다.

#### 수정 권장

입력을 다음 단계로 나눈다.

1. 생산계획
2. 일정
3. 담당자
4. 최종 확인

완료한 구역은 접고, 오류가 있는 구역만 다시 펼친다. 담당자는 기본값을 먼저 보여 주고 변경할 때만 전체 목록을 연다.

### 6.6 구매

#### 장점

- 사급과 도급을 탭으로 구분한다.
- 프로젝트를 펼쳐 구매 품목을 확인하는 구조가 명확하다.
- 구매 입력과 프로젝트 상세를 연결할 수 있다.

#### 단점

- 실제 표가 약 738px에서 시작한다.
- 구매 입력 화면에 조작 요소 33개와 여러 작업 영역이 있다.
- 한 번 클릭은 펼치기, 두 번 클릭은 프로젝트 이동이라는 숨은 동작은 발견하기 어렵다.
- 여러 저장 또는 행 단위 동작이 보이면 어디까지 저장됐는지 판단하기 어렵다.

#### 수정 권장

- 한 번 클릭은 프로젝트 펼치기만 수행한다.
- 전체 입력 이동은 `구매 입력` 버튼으로 명시한다.
- 저장 책임을 화면 전체 또는 구역별 중 하나로 통일한다.
- 구역별 저장을 유지한다면 `이 구역만 저장됩니다`를 표시한다.
- KPI와 필터를 압축해 첫 프로젝트 행을 첫 화면에 노출한다.

### 6.7 자재

#### 장점

- 입고 관리와 패널 키팅을 먼저 선택하는 구조가 명확하다.
- 입고 관리가 프로젝트 → 구매 품목 순으로 구성돼 데이터 소속을 이해하기 쉽다.
- 프로젝트를 펼친 뒤 도착 입력과 입고 현황을 함께 볼 수 있다.

#### 단점

- 프로젝트 목록이 약 705px부터 시작한다.
- 상단 이동 버튼, 요약, 검색, 사급·도급 필터, 내보내기가 목록 앞에 누적된다.
- 실제로 자주 쓰는 `도착 입력`과 `입고 확정`이 첫 진입 시 보이지 않는다.
- 업무가 두 개뿐인 업무 선택 화면은 넓은 PC에서 하단 여백이 과도하다.

#### 수정 권장

- KPI를 작은 카드 한 줄로 압축한다.
- 검색과 사급·도급 필터를 같은 줄에 둔다.
- 내보내기는 보조 도구로 내린다.
- 프로젝트 행에 미입고, 부분 입고, IQC 대기, 입고 확정 건수를 표시한다.
- 펼친 품목에서는 `도착 입력`을 기본 행동으로 가장 강하게 보여 준다.
- 업무 선택 화면의 여백에는 최근 처리 프로젝트나 오늘 대기 건수를 표시할 수 있으나, 새로운 업무 기능으로 확대하지 않는다.

### 6.8 제조

#### 장점

- KPI가 약 220px, 프로젝트 목록이 약 421px에서 시작해 첫 화면 밀도가 좋다.
- 프로젝트를 연 뒤 선택한 프로젝트의 패널만 표시한다.
- 패널 10개 이상을 왼쪽 세로 목록에서 안정적으로 탐색할 수 있다.
- 현재 단계와 진행률을 패널 단위로 확인할 수 있다.

#### 단점

- 입력 화면 높이가 약 1,531px이고 조작 요소가 43개다.
- 체크박스가 Excel 선택과 일괄 조립 단계 완료에 함께 사용될 수 있어 의미가 복잡하다.
- 패널 행 선택과 체크박스 선택의 차이를 설명 없이 이해하기 어렵다.
- 선행 조건 때문에 버튼이 비활성화될 때 원인이 충분히 가까이 표시되지 않으면 오류로 오해할 수 있다.

#### 수정 권장

- 기본 상태에서는 체크박스를 숨긴다.
- `일괄 처리` 또는 `선택 내보내기`를 누르면 다중 선택 모드로 전환한다.
- 다중 선택 모드 상단에 현재 목적과 선택 수를 표시한다.
- 비활성 버튼 옆에 필요한 선행 조건을 한 줄로 표시한다.
- 패널 입력 영역과 일괄 처리 영역을 시각적으로 분리한다.

### 6.9 품질

#### 장점

- IQC, LQC, OQC, 전진검수, FAT를 업무 선택 단계에서 분리한다.
- LQC·OQC·전진검수·FAT는 프로젝트를 선택한 뒤 패널 단위로 입력한다.
- LQC 입력 화면은 약 873px로 비교적 짧고 세로 패널 목록의 밀도가 좋다.
- 검사 준비 상태에서 시작 행동이 명확하다.

#### 단점

- 제조와 마찬가지로 체크박스와 현재 패널 선택의 의미가 겹친다.
- 조회 전용 사용자가 들어왔을 때 권한 안내가 일관되지 않다.
- 재검사 대상과 일반 검사 대상이 목록에서 충분히 강하게 구분되지 않을 수 있다.
- 검사 단계가 많을수록 현재 단계와 남은 단계 수를 한눈에 보기 어렵다.

#### 수정 권장

- 검사 입력 패널 선택과 Excel 내보내기 선택을 분리한다.
- 재검사 대상에는 `재검사` 문구와 부적합 항목 수를 함께 표시한다.
- 모든 품질 화면에 공통 조회 전용 배너를 적용한다.
- 패널 행에 `현재 단계 / 전체 단계`, Pending 여부, 다음 가능 업무를 표시한다.

### 6.10 물류

#### 장점

- 포장, 출발, 납품을 각각 독립 업무로 분리했다.
- 프로젝트 목록을 먼저 거치므로 다른 프로젝트 데이터를 잘못 수정할 가능성이 낮다.
- 패널별 처리와 증빙 입력을 연결하는 업무 방향이 적절하다.

#### 단점

- 화면에 따라 뒤로가기가 화살표만 표시되는 등 탐색 문구가 일관되지 않다.
- 포장·출발·납품의 입력 구조가 완전히 같은 규칙으로 보이지 않으면 사용자가 업무마다 다시 학습해야 한다.
- 검수 데이터에 실제 대기 프로젝트가 없을 때 빈 화면이 다음 행동을 충분히 설명하지 않는다.

#### 수정 권장

- 포장·출발·납품의 입력 순서를 `패널 선택 → 증빙 입력 → 처리 저장`으로 통일한다.
- 버튼의 위치와 문구도 세 업무에서 동일하게 유지한다.
- 아이콘 단독 뒤로가기 대신 이동 목적지를 문구로 표시한다.
- 빈 상태에서 업무가 생성되는 선행 조건을 안내한다.

### 6.11 Pending

#### 장점

- KPI가 약 220px, 프로젝트 목록이 약 421px에서 시작한다.
- 첫 화면에서 실제 Pending 프로젝트를 바로 볼 수 있다.
- 프로젝트 상세에 들어가면 다른 프로젝트 선택을 반복하지 않는다.
- 이슈 카드가 첫 화면 안에서 시작하고 코멘트·이력·조치 흐름이 연결된다.
- 현재 프로젝트의 이슈만 보여 줘 프로젝트 혼입 가능성을 줄였다.

#### 단점

- 조치 담당자, 품질 담당자, 참고 부서가 각각 무엇을 작성할 수 있는지 화면에서 더 명확히 구분할 필요가 있다.
- 재검사 대기, 조치 요청, 조치 중, 종결 상태가 비슷한 위치에 표시되면 다음 담당자가 해야 할 행동이 불분명해질 수 있다.

#### 수정 권장

- 상태마다 `현재 담당`, `다음 행동`, `대기 대상`을 한 줄로 표시한다.
- 조치 입력, 품질 재검사, 타 부서 코멘트를 영역 제목으로 구분한다.
- 프로젝트 목록과 상세의 KPI 기준이 동일하게 보이도록 용어를 통일한다.

Pending의 전체 구조는 현재 가장 좋은 화면 중 하나이며 다른 프로젝트형 업무 화면의 기준으로 사용할 수 있다.

### 6.12 내 업무와 알림

#### 장점

- 데이터가 있을 때 프로젝트별 그룹과 상세 내용 열을 제공한다.
- 동일 프로젝트에서 발생한 여러 업무를 함께 이해하기 쉽다.
- 이동 버튼을 통해 실제 업무 화면으로 직접 연결할 수 있다.

#### 단점

- 빈 상태가 한 줄 설명으로 끝난다.
- 사용자는 데이터가 없는 것인지 필터·갱신 문제인지 구분하기 어렵다.
- 일상 처리 화면에서 내보내기 기능이 기본 업무 행동과 경쟁한다.
- 상세 내용이 길면 한 행의 높이가 커지고 빠른 훑어보기가 어려워진다.

#### 수정 권장

- 빈 상태에 마지막 갱신 시간, 필터 초기화, 새로고침을 제공한다.
- 상세 내용은 핵심 변경 한 줄을 먼저 표시하고 전문은 펼친다.
- 내보내기는 보조 메뉴로 이동한다.
- 프로젝트 그룹 헤더에 대기 업무 수와 가장 긴급한 상태를 표시한다.

### 6.13 영업 대시보드

#### 장점

- 월별 실적, 목표, 달성률을 12개월 그래프로 비교할 수 있다.
- 금액 KPI와 월별 상세 자료가 함께 있어 관리 관점에서 유용하다.
- 영업 사용자의 홈과 영업 메뉴 모두 부서 특화 정보를 제공한다.

#### 단점

- 데이터가 없을 때 큰 그래프가 빈 공간처럼 보인다.
- 영업 홈에서는 그래프가 일상 업무보다 먼저 나온다.
- 관리 KPI와 실무 행동의 우선순위가 혼재한다.

#### 수정 권장

- 홈은 오늘 업무를 먼저, 영업 대시보드는 분석 그래프를 먼저 보여 주도록 역할을 구분한다.
- 데이터가 없을 때 목표 또는 실적 입력 경로를 안내한다.
- 그래프 하단의 월별 근거 표는 접을 수 있게 한다.

### 6.14 양식 관리

#### 장점

- 양식 목록, 버전, 편집 영역을 세 단계로 구분한다.
- 활성 버전과 편집 초안을 분리하려는 정책은 안전하다.
- 코드 수정 없이 양식을 관리할 수 있는 기반이 있다.

#### 단점

- 전체 화면 높이가 약 1,602px이다.
- 조작 요소가 약 83개, 입력 요소가 약 34개로 매우 복잡하다.
- 조회 중인 활성 버전도 비활성화된 입력창으로 표시해 사용자가 입력 오류로 오해할 수 있다.
- 편집 전과 편집 중의 시각적 차이가 충분히 크지 않으면 저장 버튼을 찾기 어렵다.

#### 수정 권장

- 조회 상태에서는 input을 사용하지 않고 일반 텍스트 미리보기로 표시한다.
- `편집`을 눌렀을 때만 실제 입력 요소로 전환한다.
- 편집 중임을 상단 고정 배너로 알린다.
- 저장·취소를 화면 하단에 고정한다.
- 항목 추가·삭제·순서 변경은 별도 `구조 편집` 모드로 분리한다.

### 6.15 관리자 화면

#### 장점

- 운영 상태와 관리 기능을 한곳에서 확인할 수 있다.
- 관리 기능이 운영, 시스템 관리, 조회 범주로 구분돼 있다.
- Pending 유형 관리처럼 표가 첫 화면에 들어오는 세부 화면은 사용성이 좋다.

#### 단점

- 큰 운영 상태 카드 아래에 실제 관리 기능이 배치된다.
- 관리자가 특정 설정을 변경하려면 불필요한 스크롤이 생길 수 있다.
- 기능이 늘어날수록 카드형 관리자 홈은 탐색 속도가 떨어진다.

#### 수정 권장

- 자주 쓰는 관리 기능 바로가기를 상단에 배치한다.
- 운영 상태는 한 줄 요약으로 축소한다.
- `사용자·권한 / 양식·코드 / 알림·연동 / 운영 상태`의 보조 메뉴를 제공한다.

## 7. 입력 UX 평가

### 7.1 좋은 입력 패턴

다음 입력 패턴은 유지해야 한다.

- 한 프로젝트 안에서만 입력하도록 URL과 화면 경계를 고정
- 왼쪽 세로 패널 목록으로 대상 선택
- 필수값과 현재 상태를 입력 가까이에 표시
- 하단 고정 저장 바
- 저장 불가 시 버튼 비활성화와 사유 표시
- 완료 전 확인이 필요한 업무에서 명시적 판정 버튼 제공

### 7.2 개선이 필요한 입력 패턴

#### 모든 입력을 한 번에 펼치는 방식

생산관리처럼 40개 이상의 입력을 한 화면에 펼치면 전체 길이와 인지 부담이 커진다. 입력 항목을 삭제하지 않고 단계형 또는 접기형으로 바꿔야 한다.

#### 비활성 input을 조회 UI로 사용하는 방식

양식 관리처럼 조회 상태를 disabled input으로 표현하면 사용자는 권한 또는 시스템 오류로 오해한다. 조회와 편집은 시각적으로 다른 컴포넌트를 사용해야 한다.

#### 저장 책임이 여러 곳에 있는 방식

페이지 저장, 행 저장, 섹션 저장이 함께 있으면 어디까지 확정됐는지 알기 어렵다. 한 화면 안에서는 저장 책임을 하나로 통일하거나 각 저장 범위를 명시해야 한다.

#### 선행 조건만으로 버튼을 비활성화하는 방식

버튼이 비활성화되어도 이유를 바로 알 수 있어야 한다. 버튼 주변에 `LQC 완료 후 OQC를 시작할 수 있습니다`처럼 다음 조건을 표시해야 한다.

## 8. 시각 디자인 평가

### 8.1 장점

- 흑백과 1px 경계 중심의 구조는 업무 데이터에 집중하기 좋다.
- 상태 색상이 상대적으로 잘 드러난다.
- 사각형 기반 요소가 표와 입력 화면에 적합하다.
- 과도한 그림자와 장식이 줄어 전문 업무 도구의 성격에 맞는다.

### 8.2 단점

- 공통 흑백 스타일이 기존 대형 스타일 파일 위에 덮이는 구조라 화면별 미세한 차이가 남는다.
- 일부 페이지는 공통 헤더를 사용하고 다른 페이지는 자체 헤더를 사용한다.
- 헤더 높이, 설명 위치, 버튼 정렬이 화면마다 조금씩 달라 통일감이 약해진다.
- textarea 입력 글자가 실제 상태와 관계없이 성공 색상처럼 보일 수 있는 스타일이 남아 있다.
- 장식성 영문 eyebrow가 정보 밀도를 높이지 않으면서 공간을 사용한다.

### 8.3 수정 권장

- 공통 페이지 헤더를 모든 업무 페이지에 적용한다.
- KPI, 필터, 프로젝트 표, 빈 상태, 조회 전용 배너를 공통 컴포넌트로 통합한다.
- 상태 의미가 없는 입력 텍스트에는 검정색을 사용한다.
- 기존 색상·그림자·큰 둥근 모서리 규칙을 제거하고 wireframe 규칙을 원본 스타일로 승격한다.
- 장식용 영문은 제거하거나 보조 설명 수준으로 축소한다.

## 9. 접근성 및 오류 예방 평가

### 장점

- 상태를 색상과 문구로 함께 표시한다.
- 일부 프로젝트 행은 키보드로 열 수 있다.
- 체크박스 클릭과 행 이동의 이벤트 충돌을 방지한 화면이 있다.
- 입력 label과 tab 역할이 주요 화면에 적용돼 있다.

### 단점

- 커스텀 표가 일반 HTML table과 다른 역할 구조를 사용해 보조기기 탐색의 일관성이 떨어질 수 있다.
- 아이콘만 있는 뒤로가기는 목적지를 알기 어렵다.
- 체크박스와 클릭 가능한 패널 행이 붙어 있어 조작 대상이 중복된다.
- 조회 전용 화면에서 버튼만 비활성화하면 권한과 선행 조건을 구분하기 어렵다.
- 빈 상태가 복구 행동을 제공하지 않는다.

### 수정 권장

- 표는 가능한 한 공통 semantic table을 사용한다.
- 아이콘 버튼에 화면상 텍스트 또는 충분한 accessible name을 제공한다.
- 현재 선택과 다중 선택을 서로 다른 모드로 분리한다.
- 오류, 권한, 선행 조건 메시지를 서로 다른 표현으로 구분한다.
- 빈 상태에 새로고침, 필터 초기화, 관련 화면 이동을 제공한다.

## 10. 수정 우선순위

### P1 — 실제 업무 속도와 오류 가능성에 직접 영향을 주는 문제

#### P1-1. 프로젝트·구매·자재의 첫 화면에 실제 목록 노출

- KPI 높이를 축소한다.
- 필터를 한 줄로 정리한다.
- 선택 내보내기는 항목 선택 후에만 표시한다.
- 1280×720에서 최소 2개 프로젝트 행을 보여 준다.

#### P1-2. 프로젝트 상세 상단 압축과 탭 고정

- 핵심 기본 정보만 1~2행으로 유지한다.
- 나머지는 펼치기로 이동한다.
- 탭은 첫 화면 안에 배치하고 스크롤 시 고정한다.
- 병목 현황은 간단한 요약 줄로 축소한다.

#### P1-3. 조회 전용 안내 통일

- 타 부서 화면 상단에 공통 배너를 표시한다.
- 입력 버튼을 비활성화할 때 권한 부족인지 선행 조건 부족인지 구분한다.
- 조회 전용에서도 이동·검색·내보내기는 정상적으로 사용할 수 있게 한다.

#### P1-4. 제조·품질의 다중 선택 의미 분리

- 기본 패널 선택과 일괄 처리 선택을 분리한다.
- 다중 선택 모드에서만 체크박스를 표시한다.
- 선택 목적과 선택 개수를 고정 영역에 표시한다.

#### P1-5. 영업 홈의 일상 업무 우선순위 수정

- 오늘 내 업무·긴급 Pending·새 알림을 매출 그래프 위에 배치한다.
- 매출 분석은 영업 대시보드에서 더 상세히 제공한다.

### P2 — 학습 비용과 화면 일관성을 개선하는 문제

#### P2-1. 경로와 뒤로가기 통일

- `부서 > 업무 > 프로젝트 > 패널` breadcrumb를 적용한다.
- 아이콘 단독 뒤로가기를 제거한다.

#### P2-2. 생산관리 입력 단계화

- 계획, 일정, 담당자, 확인으로 구분한다.
- 완료 구역 자동 접기와 오류 구역 자동 펼치기를 적용한다.

#### P2-3. 양식 관리 조회·편집 분리

- 조회는 텍스트 미리보기로 제공한다.
- 편집 시에만 input을 렌더링한다.
- 편집 상태와 저장 위치를 고정 표시한다.

#### P2-4. 빈 상태 개선

- 빈 이유와 마지막 갱신 시간을 표시한다.
- 새로고침, 필터 초기화, 관련 화면 이동을 제공한다.

#### P2-5. 보조 기능 정리

- Excel 내보내기와 고급 필터를 `추가 기능`으로 이동한다.
- 일상 업무의 기본 버튼과 시각적으로 경쟁하지 않게 한다.

#### P2-6. 용어와 문구 정리

- 한국어 중심으로 통일한다.
- `후속 단계에서 제공됩니다`처럼 현재 구현과 맞지 않는 오래된 안내를 제거한다.
- 완료, 확정, 저장, 요청의 의미를 부서별로 동일하게 사용한다.

### P3 — 장기 유지보수와 성능 문제

#### P3-1. 공통 컴포넌트 적용 확대

- 페이지 헤더
- KPI
- 필터 바
- 프로젝트 표
- 빈 상태
- 조회 전용 배너
- 고정 저장 바

각 요소를 공통 디자인 시스템으로 통합한다.

#### P3-2. 기존 스타일 정리

- 기존 색상, gradient, shadow, 큰 radius 규칙을 제거한다.
- 흑백 wireframe을 override가 아닌 기본 스타일로 만든다.
- 상태와 무관한 성공색 입력 텍스트를 수정한다.

#### P3-3. Frontend 크기와 분리

- 큰 `App`과 대형 스타일 파일을 화면·업무 단위로 분리한다.
- 부서별 입력 화면을 지연 로딩한다.
- 신규 화면이 기존 화면 스타일을 깨뜨릴 위험을 줄인다.

#### P3-4. 관리자 탐색 구조 개선

- 관리자 기능을 보조 메뉴로 분리한다.
- 운영 상태와 실제 관리 행동의 우선순위를 나눈다.

## 11. 권장 구현 순서

기능을 유지하면서 UX만 개선하려면 다음 순서가 가장 안전하다.

1. 공통 목록 화면의 높이와 첫 행 노출 기준 확정
2. 프로젝트·구매·자재 목록 밀도 수정
3. 프로젝트 상세 요약 압축과 탭 고정
4. 공통 조회 전용 배너 적용
5. 제조·품질 다중 선택 모드 분리
6. 영업 홈의 일상 업무 우선 배치
7. 공통 breadcrumb와 뒤로가기 적용
8. 생산관리 단계형 입력 적용
9. 양식 관리 조회·편집 분리
10. 빈 상태와 보조 기능 정리
11. 공통 컴포넌트·기존 스타일·bundle 구조 정리

이 순서는 먼저 실제 업무 속도와 오류 예방 문제를 해결한 뒤, 화면 일관성과 내부 유지보수 문제를 정리한다.

## 12. 수정 시 지켜야 할 불변조건

다음 기능은 UX 수정 과정에서 변경하거나 삭제하면 안 된다.

- 부서별 권한과 타 부서 조회 정책
- 프로젝트 단위 데이터 경계
- 패널 단위 제조·LQC·OQC·전진검수·FAT·물류 처리
- 제조·품질의 세로 패널 목록
- Pending의 프로젝트별 목록과 한 프로젝트 상세 구조
- 상태 의미 색상과 상태 텍스트 동시 표시
- 선택 Excel 내보내기 기능
- 하단 고정 저장 바
- 내 업무·알림의 프로젝트 그룹
- 알림·내 업무 deep link
- 기존 API, 상태 전이, 저장·확정 로직

이번 권장안의 목적은 기능을 바꾸는 것이 아니라 사용자가 같은 기능을 더 빨리 찾고, 더 적은 실수로 입력하게 만드는 것이다.

## 13. 완료 기준

향후 PC UX 보완 작업은 다음 기준을 만족해야 완료로 볼 수 있다.

### 공통

- [ ] 1280×720에서 가로 스크롤이 발생하지 않는다.
- [ ] 프로젝트형 목록 화면의 첫 프로젝트 행이 첫 화면 안에 표시된다.
- [ ] 타 부서 화면은 상단에서 조회 전용 여부를 즉시 알 수 있다.
- [ ] 뒤로가기 목적지가 모든 화면에서 문구로 표시된다.
- [ ] 기본 행동과 내보내기·고급 필터 같은 보조 행동이 시각적으로 구분된다.

### 프로젝트 상세

- [ ] 부서 탭이 720px 첫 화면 안에 표시된다.
- [ ] 핵심 기본 정보는 1~2행으로 압축된다.
- [ ] 상세 기본 정보는 필요할 때 펼칠 수 있다.
- [ ] 탭은 스크롤 중에도 접근할 수 있다.

### 입력 화면

- [ ] 현재 프로젝트와 패널이 항상 명확하다.
- [ ] 현재 항목 선택과 다중 선택의 의미가 분리된다.
- [ ] 비활성 버튼은 이유와 다음 조건을 함께 표시한다.
- [ ] 저장 범위와 저장 완료 여부를 즉시 알 수 있다.
- [ ] 조회 상태를 disabled input으로 표현하지 않는다.

### 홈과 공통 업무

- [ ] 영업 홈에서 오늘 내 업무와 긴급 Pending이 첫 화면에 보인다.
- [ ] 빈 상태는 이유, 갱신 방법, 다음 행동을 안내한다.
- [ ] 내 업무와 알림의 긴 상세 내용은 요약 후 펼칠 수 있다.

## 14. 최종 결론

현재 PC UX/UI는 기능적으로는 충분하지만 아직 조직 전체가 설명 없이 바로 사용할 만큼 단순하지는 않다. 숙련 사용자는 원하는 기능을 찾아 처리할 수 있지만, 신규 사용자와 타 부서 조회 사용자는 다음 부분에서 반복적으로 멈출 가능성이 높다.

- 실제 목록을 보기 전 스크롤
- 조회 전용인지 오류인지 판단
- 체크박스와 현재 입력 대상 선택 구분
- 긴 입력 화면에서 시작 위치 판단
- 조회 화면과 편집 화면 구분
- 화면마다 다른 뒤로가기와 저장 방식 학습

가장 먼저 해야 할 일은 새 기능 추가가 아니라 첫 화면의 정보 우선순위를 바로잡는 것이다. 프로젝트·구매·자재 목록을 첫 화면에 보여 주고, 프로젝트 상세 탭을 상단으로 올리며, 조회 전용과 다중 선택을 명확히 하면 사용자가 체감하는 속도와 신뢰도가 크게 좋아질 수 있다.

제조·품질·Pending에서 이미 잘 작동하는 구조를 공통 기준으로 삼고 다른 화면을 같은 규칙에 맞추는 것이 가장 안전하고 효과적인 개선 방향이다.
