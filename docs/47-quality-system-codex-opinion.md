## 1. 결론부터

현재 사이트의 품질 시스템은 “검사를 디지털로 입력한다”는 기반은 잘 갖춰져 있지만, 실제 현장과 비교하면 **검사 대상 선정**, **검사 기준의 적용 범위**, **외부 문서와 내부 검사 연결**, **도면 revision 대조**가 빠져 있다.

가장 중요한 수정 방향은 다음 네 가지다.

1. 모든 구매품을 같은 IQC로 보내지 말고 구매품마다 `검사 미대상 / 간이검사 / 정식검사`를 구조적으로 지정한다.
2. 외함은 협력사 검사서와 EMI 추가 검사·서명을 한 건의 `IQC 검사 묶음`으로 관리한다.
3. LQC와 OQC는 하나의 고정 체크리스트가 아니라 `공통 기준 + 제품 조건 + 프로젝트 특이사항`을 조합해 프로젝트별 검사계획을 만든다.
4. 품질 담당자가 검사 화면에서 해당 패널의 최신 확정 도면과 과거 검사·Pending 근거를 함께 보게 한다.

핵심은 성적서 수를 무조건 늘리는 것이 아니다. **검사한 사실은 모두 기록하되, 공식 성적서는 업무상 필요한 수준으로만 발행**해야 한다.

## 2. 현장 방식과 현재 시스템의 차이

| 영역 | 실제 현장 | 현재 사이트 | 문제 |
| --- | --- | --- | --- |
| IQC 대상 | 외함·판금류·부스바·명판만 검사 | 모든 구매품 도착분에 IQC 자동 생성 | 불필요한 업무가 생성되고 실제 대상 판별이 불가능 |
| IQC 문서 | 외함만 공식 검사서, 나머지는 육안 확인 | 모든 도착분이 같은 상세 성적서 구조 | 기록 수준과 공식 문서 수준이 구분되지 않음 |
| 외함 검사서 | 협력사 작성 원본에 EMI가 추가 검사·서명 | 시스템 내부 양식만 작성 | 협력사 원본과 EMI 판정이 분리됨 |
| LQC | 실제 검사는 하지만 기준서·성적서 없음 | 일반 LQC 체크리스트 제공 | 제조 단계별 실제 기준과 연결되지 않음 |
| OQC | 프로젝트 특이사항에 따라 계속 변함 | 활성 OQC 양식 하나를 검사 시작 시 적용 | 프로젝트별 조건·과거 문제·고객 요청을 선택 적용하기 어려움 |
| 전진검수/FAT | 기존 성적서·도면·실물을 종합 확인하고 고객 서명 | 합격/부적합 중심의 독립 검사 단계 | 고객에게 제시하는 검사 묶음과 서명본 관리가 약함 |
| 도면 | 종이 도면을 들고 실물 대조 | 체크 항목에 “도면 일치”만 존재 | 어떤 revision을 봤는지 증명할 수 없음 |

## 3. IQC는 “품목명 추측”이 아니라 “검사 분류”로 연결해야 한다

구매팀이 `외함`, `함체`, `판넬 외함`, 업체 모델명처럼 자유롭게 입력한 문자열만 보고 시스템이 자동 판단하게 하면 반드시 누락과 오분류가 생긴다. 문자열 자동 분류는 보조 기능으로만 쓰고 최종 분류는 구조화된 값으로 저장해야 한다.

### 권장 입력값

구매품목에 다음 값을 추가하는 방식을 권장한다.

- 품질 분류: `외함 / 판금류 / 부스바 / 명판 / 기타`
- 검사 수준:
  - `검사 미대상`
  - `간이 IQC`
  - `정식 IQC`
- 적용 검사 양식
- 협력사 검사서 필요 여부
- 검사 단위: `도착분 전체 / Lot / 표본`

기본 연결은 다음과 같이 둔다.

| 품질 분류 | 기본 검사 수준 | 기본 문서 |
| --- | --- | --- |
| 외함 | 정식 IQC | 협력사 원본 + EMI 검사 기록 + 확정 PDF |
| 판금류 | 간이 IQC | 디지털 간이 검사 기록 |
| 부스바 | 간이 IQC | 디지털 간이 검사 기록 |
| 명판 | 간이 IQC | 디지털 간이 검사 기록 |
| 기타 | 검사 미대상 | 입고 확인 이력만 |

구매 담당자가 품목을 등록할 때 시스템이 품목명 alias로 분류를 추천할 수는 있다. 다만 `자동 확정`은 하지 않고 구매 담당자가 선택하며, 품질팀이 첫 입고 전까지 수정할 수 있게 한다.

분류가 `미확정`인 상태로 물건이 도착하면 도착 등록 자체는 허용하되 바로 품질 분류 확인 업무를 생성하고, 분류가 끝나기 전에는 입고 확정을 막는 것이 안전하다. 이렇게 해야 현장 입고가 멈추지 않으면서 검사 누락도 막을 수 있다.

### 검사 미대상 품목

검사 미대상 품목은 도착 즉시 자재의 입고 확정 대상으로 보내야 한다. 현재처럼 모든 도착분에 IQC 업무를 생성하면 품질팀 업무함이 실제 업무량을 반영하지 못한다.

## 4. 판금류·부스바·명판도 기록은 남기되 “공식 성적서”를 강제하지 않는다

사용자의 생각처럼 현재 눈으로만 확인하는 검사도 기준과 이력은 만드는 것이 좋다. 부적합이 발생했을 때 “누가 무엇을 확인했는가”가 남아야 같은 문제가 반복되지 않기 때문이다.

다만 세 품목에 처음부터 외함과 같은 무거운 성적서를 강제하는 것은 권장하지 않는다.

### 권장 수준

- 판금류: 치수·가공 상태·도장/표면·도면/발주 사양 일치
- 부스바: 재질·규격·수량·가공 치수·도금/표면·손상
- 명판: 문구·도면 revision·재질·색상·수량·오탈자

각 도착분에서 위 항목을 빠르게 체크하고 검사자·일시·판정·사진·특이사항을 저장한다. 이것을 시스템 내부에서는 모두 `검사 기록`으로 부르되, 외부 제출 또는 공식 보관이 필요한 경우에만 `성적서 PDF`를 생성한다.

즉, **모든 검사에는 기록이 있지만 모든 검사에 무거운 공식 성적서가 필요한 것은 아니다.**

## 5. 외함은 협력사 검사서와 EMI 검사를 하나의 묶음으로 관리한다

외함은 현재 프로세스를 없애기보다 디지털로 연결해야 한다.

### 권장 흐름

1. 양식 관리에서 외함 협력사용 검사 양식을 관리한다.
2. 구매 발주 시 해당 양식 revision을 협력사 전달 대상으로 고정한다.
3. 외함 입고 시 자재 또는 품질이 협력사 작성 검사서의 PDF·사진을 첨부한다.
4. 품질 담당자는 같은 화면에서 협력사 검사 결과를 확인한다.
5. EMI 추가 검사항목을 입력하고 서명 또는 검사자 확정을 한다.
6. 시스템은 다음을 하나의 `IQC 검사 묶음`으로 확정한다.
   - 협력사 원본 검사서
   - EMI 추가 검사 결과
   - 부적합·Pending·재검사 이력
   - 최종 판정
   - 확정 시점의 통합 표지 또는 PDF

초기에는 종이 서명을 스캔한 원본을 그대로 보존하는 것이 현실적이다. OCR로 종이 체크값을 자동 인식하는 기능은 오인식 검증 비용이 크므로 1차 도입 범위에서는 제외하는 편이 좋다.

협력사 원본은 EMI가 수정해서는 안 된다. 업로드한 원본과 EMI가 추가한 검사 데이터는 물리적으로 구분하고, 최종 화면과 출력에서만 한 묶음으로 보여줘야 한다.

## 6. LQC는 반드시 기준을 만들되 제조 단계에 붙여야 한다

LQC를 별도의 큰 검사서 한 장으로 만들면 실제 제조 흐름과 다시 분리될 가능성이 높다. LQC는 제조 중간 검사이므로 `제조 단계별 LQC 기준`으로 구성하는 것이 맞다.

### 권장 구조

각 제조 단계에 다음 중 하나를 연결한다.

- LQC 없음
- 필수 LQC
- 표본 LQC
- 확인 항목 묶음

예를 들어 제조 단계가 `부스바 조립`, `기기 취부`, `배선`, `마감`이라면 각 단계에 필요한 LQC 항목을 연결한다. 제조 단계가 시작되면 해당 패널의 LQC 업무가 동시에 열리고, 품질팀은 현장에서 해당 단계만 검사한다.

제조 단계 자체의 작업 완료 입력은 허용하되, 필수 LQC가 남아 있으면 패널은 OQC로 넘어갈 수 없게 하는 방식을 권장한다. 제조가 품질 담당자의 입력 때문에 작업 기록조차 못 하는 구조는 피해야 하지만, 품질 확인 없이 최종 단계로 넘어가는 것은 막아야 한다.

패널 하나의 모든 단계별 LQC가 끝나면 시스템이 이를 모아 `패널 LQC 성적서`를 생성한다. 현장에서는 단계별로 짧게 입력하고, 문서는 패널 단위로 한 번에 확인할 수 있는 구조다.

## 7. OQC는 “항목을 계속 쌓는 방식”에서 “적용 규칙을 가진 항목 도서관”으로 바꾼다

과거 문제와 고객 요청을 계속 OQC에 추가하는 방향 자체는 맞다. 문제는 모든 항목을 하나의 체크리스트에 영구 누적하면 프로젝트가 늘수록 검사서가 길어지고 `N/A`가 대부분을 차지한다는 점이다.

### 권장 3층 구조

1. 공통 필수 기준
   - 모든 프로젝트 또는 해당 Item에 항상 적용
2. 조건부 기준 묶음
   - 문/경첩, 특정 기기, 특정 회로, 특정 포장, 고객별 요구사항처럼 조건이 맞을 때만 적용
3. 프로젝트 추가 항목
   - 이번 프로젝트의 특이사항, 고객 요청, 설계 검토, 이전 Pending 재발 방지 항목

과거 문제를 OQC 항목으로 추가할 때는 단순 문장만 넣지 말고 다음을 함께 기록해야 한다.

- 문제 출처
- 적용 대상 Item·고객·부품·구조
- 적용 조건
- 확인 방법과 합격 기준
- 중요도
- 적용 시작일
- 재검토일 또는 종료 조건
- 관련 Pending·고객 불만 근거

품질팀장이 후보 항목을 검토해 `검사 기준 도서관`에 등록하면 새 프로젝트의 OQC 계획을 만들 때 시스템이 적용 후보를 추천한다. 과거 Pending이나 고객 불만이 발생했다고 모든 프로젝트에 자동 추가하면 안 된다.

### 제외와 N/A의 권장 기준

- 프로젝트에 문이 없다는 사실을 설계 데이터로 미리 알 수 있다면 경첩 검사항목은 **프로젝트 OQC 계획에서 제외**한다.
- 제외된 항목과 제외 사유는 검사 계획 이력에 남기되 최종 성적서 본문에는 표시하지 않는다.
- 검사 계획에는 포함됐지만 실제 제품 변경 등으로 현장에서 적용할 수 없게 된 경우에만 `N/A`를 사용한다.
- `N/A`는 사유 입력을 필수로 한다.

이 방식이면 성적서는 실제 제품에 필요한 항목만 보여 간결하고, 감사 관점에서는 왜 특정 항목이 빠졌는지도 확인할 수 있다.

프로젝트 OQC 계획은 첫 OQC 시작 전에 revision을 확정한다. 검사 시작 후 항목을 바꾸려면 변경 사유와 새 revision을 만들고, 이미 완료된 패널의 성적서는 기존 revision을 유지해야 한다.

## 8. 전진검수와 FAT는 “새 검사서 작성”보다 “고객 검수 패키지”가 중심이다

전진검수와 FAT 화면의 중심은 적합/부적합 체크리스트가 아니라 고객에게 보여줄 자료의 준비 상태여야 한다.

### 고객 검수 패키지 구성

- 프로젝트와 패널 기본정보
- 확정 도면 목록과 revision
- 해당되는 IQC 검사 기록 및 외함 협력사 원본
- 패널별 LQC 성적서
- 패널별 OQC 성적서
- 열린 Pending 0건 확인과 종결 이력 요약
- 고객 요청사항 반영 결과
- 제품·시험 사진
- OQC를 요약한 고객용 성적서

전진검수 또는 FAT 당일에는 고객 확인 결과, 참석자, 지적사항, PUNCH, 서명본을 등록한다. 초기에는 종이에 받은 서명본을 촬영·스캔해 원본으로 보존하고, 전자서명은 별도 단계로 검토하는 것이 안전하다.

전진검수와 FAT 자체의 판정 흐름은 현재처럼 패널별 합격/부적합·Pending으로 유지하되, 사용 화면은 `검사 패키지 준비 → 고객 확인 → 서명본 등록 → 완료`로 재구성하는 것이 현장 의미에 더 맞다.

## 9. 도면은 검사 화면의 참고파일이 아니라 검사 근거가 되어야 한다

단순히 도면 파일을 첨부하는 것만으로는 부족하다. 검사자가 어떤 revision을 보고 판정했는지가 성적서에 남아야 한다.

### 권장 도면 구조

- 설계가 프로젝트 또는 패널별 도면 PDF를 등록한다.
- 도면번호, revision, 발행 상태, 발행일, 대상 패널을 저장한다.
- `검사용 확정` 상태의 최신 revision만 현장 기본 화면에 표시한다.
- 새 revision이 발행되면 이전 revision은 삭제하지 않고 보관한다.
- 검사 시작 시 사용한 도면 revision을 검사 attempt에 snapshot한다.
- 검사 완료 후 도면이 바뀌어도 기존 성적서가 참조한 revision은 바뀌지 않는다.

### 검사 화면

PC·태블릿에서는 왼쪽에 체크리스트, 오른쪽에 도면 PDF를 나란히 표시한다. 패널 QR로 들어오면 해당 패널의 검사와 최신 확정 도면이 바로 열린다.

휴대폰에서는 화면을 억지로 2분할하지 않고 다음 행동을 제공한다.

- `도면 보기` 전체 화면
- 페이지 이동·확대
- 다시 검사 항목으로 돌아가기
- 특정 항목에서 관련 도면 페이지 바로 열기

초기에는 PDF 조회와 revision 연결에 집중하고, 도면 위 위치 표시·주석·CAD 비교·오프라인 저장은 후속으로 두는 것이 좋다.

## 10. 사이트의 권장 정보구조

품질 메뉴는 다음 네 업무로 나누는 것이 명확하다.

1. 수입검사
   - 품질 분류 확인
   - 간이 IQC
   - 정식 IQC
   - 협력사 검사서 확인
2. 공정검사
   - 제조 단계별 LQC
   - 패널별 LQC 성적서
3. 최종검사
   - OQC 검사계획
   - OQC 실행
   - 과거 문제·고객 요구 기준 도서관
4. 고객검수
   - 전진검수
   - FAT
   - 고객 검수 패키지
   - 서명본

별도로 `품질 문서함`을 두어 프로젝트·패널별로 IQC/LQC/OQC/고객검수 자료와 도면 revision을 한 번에 조회하게 한다.

## 11. 필요한 핵심 데이터 개념

구현 시 기존 성적서·사진·Pending 구조를 버리기보다 다음 개념을 추가하는 것이 적절하다.

- 구매품 품질 분류와 검사 수준
- 품질 분류 alias 및 추천 규칙
- 협력사 제출 문서와 검증 상태
- 제조 단계와 LQC 기준 연결
- 검사 기준 도서관
- 기준 적용 조건
- 프로젝트별 품질 검사계획과 revision
- 검사계획 항목의 포함·제외·N/A 사유
- 과거 문제·Pending에서 생성된 검사기준 후보
- 도면 문서와 revision
- 검사 attempt가 참조한 도면 revision
- 고객 검수 패키지와 서명본

기존의 확정 성적서 불변, 재검사 이력, Pending 연결, 프로젝트 접근 권한은 그대로 유지해야 한다.

## 12. 권장 도입 순서

### 1단계 — 선택형 IQC와 품질 분류

- 외함·판금류·부스바·명판 분류
- 검사 미대상/간이/정식 routing
- 구매 입력과 품질 확인
- 외함 협력사 원본 첨부
- 검사 미대상 품목의 IQC 자동 생성 제거

이 단계가 먼저 필요한 이유는 현재 불필요한 IQC 업무가 가장 직접적으로 현장과 어긋나기 때문이다.

### 2단계 — LQC 기준과 제조 단계 연결

- 제조 단계별 LQC 항목
- 제조와 LQC 동시 시작
- 패널 LQC 종합 성적서
- OQC 인계 조건

### 3단계 — 프로젝트별 OQC 검사계획

- 공통/조건부/프로젝트 추가 항목
- 과거 문제 기준 후보와 승인
- 적용 조건과 제외/N/A 정책
- 프로젝트 OQC revision 고정

### 4단계 — 도면 대조와 품질 문서함

- 확정 도면 revision
- 검사 화면 도면 뷰어
- 검사 attempt revision snapshot
- 프로젝트·패널 품질 문서함

### 5단계 — 전진검수/FAT 고객 검수 패키지

- 자동 증빙 묶음
- 고객용 요약 성적서
- 서명본·PUNCH 연결

## 13. 구현 전에 사용자가 확정해야 할 정책

1. 구매품 품질 분류의 최종 책임자는 구매팀인지 품질팀인지
   - 권장: 구매팀 1차 선택, 품질팀 수정·최종 확인
2. 판금류·부스바·명판을 100% 검사할지 Lot/표본 검사할지
3. 세 품목의 디지털 기록을 사내 기록으로만 둘지 항상 PDF 성적서까지 발급할지
   - 권장: 기록은 필수, PDF는 고객·규정 요구 시 생성
4. 외함 협력사 검사서가 미도착하면 입고 확정을 차단할지
   - 권장: 원칙적으로 차단하되 긴급 사용은 승인·사유·기한이 있는 예외 처리
5. OQC 조건을 자동 판단할 설계·BOM 정보가 현재 충분한지
6. 과거 문제 항목의 재검토 주기와 종료 권한
7. 전진검수/FAT 고객 서명은 당분간 종이 스캔인지 전자서명인지
8. 도면의 원본 저장 위치와 `검사용 확정 revision` 승인 주체

## 14. 성공 판단 기준

- 품질 업무함에 실제 IQC 대상만 들어온다.
- 외함 입고 건마다 협력사 원본과 EMI 검사 결과를 한 화면에서 찾을 수 있다.
- 판금류·부스바·명판의 육안 검사도 검사자·판정·근거가 남는다.
- 각 제조 단계에서 필요한 LQC가 빠지지 않고 OQC 전에 완료된다.
- OQC 성적서에서 불필요한 N/A 비율이 줄고, 제외 근거는 별도로 추적된다.
- 고객 방문 전에 필요한 도면·성적서·Pending 종결 자료를 자동으로 준비할 수 있다.
- 완료 성적서에서 검사 당시 사용한 도면 revision을 재현할 수 있다.
- 품질팀이 검사 때문에 성적서와 도면을 반복 출력하지 않아도 된다.

## 15. 최종 권장안

이번 현장 조사를 단순히 “체크리스트 문구를 바꾸는 작업”으로 처리하면 안 된다. 먼저 **품목별 검사 적용 정책**과 **프로젝트별 품질 검사계획**을 시스템의 정식 데이터로 만들어야 한다.

Codex의 우선순위는 다음과 같다.

1. 선택형 IQC routing과 품질 분류
2. 외함 협력사 검사서 결합
3. 제조 단계별 LQC
4. 조건부 OQC 검사계획
5. 도면 revision 연결
6. 고객 검수 패키지

이 순서로 가면 현재 구현된 성적서·사진·PDF·Pending·재검사 기반을 대부분 재사용하면서 실제 품질팀의 종이 업무와 불필요한 입력을 줄일 수 있다.
