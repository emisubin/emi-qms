# TASK-PROJECT-ASSIGNEE-DELEGATION-001 — Codex 기획

## 1. 사용자 문제와 기대 결과

현재는 생산관리팀만 프로젝트 생산계획 수정 화면에서 모든 부서 담당자를 지정할 수 있다. 따라서 생산관리팀이 각 부서에 별도로 연락해 담당자 정보를 취합하고 대신 입력해야 한다.

완료 후에는 생산관리 이외 부서장이 프로젝트 상세의 `생산계획 수정` 버튼으로 들어가 자기 부서의 정·부 담당자만 직접 지정한다. 다른 부서 담당자와 생산계획 항목·일정·실적 연결은 이 전용 화면에 나타나지 않으며, 프로젝트 상세 조회 화면에서는 기존처럼 전체 계획과 전체 부서 담당자를 확인할 수 있다.

## 2. 역할과 권한

| 사용자 | 프로젝트 상세 조회 | 생산계획 수정 진입 | 저장 가능 범위 |
| --- | --- | --- | --- |
| 생산관리 권한 사용자 | 전체 표시 | 기존 전체 화면 | 생산계획·실적 연결·모든 부서 담당자 |
| 생산관리 이외 활성 부서장 | 전체 표시 | 자기 부서 전용 화면 | 자기 부서 담당자만 |
| 일반 사용자 | 전체 표시 | 버튼 미표시·직접 접근 차단 | 없음 |
| 다른 부서의 부서장 | 전체 표시 | 자기 부서 전용 화면 | 요청에 다른 부서 값이 있으면 서버 차단 |

- 지원 부서는 영업, 설계, 구매, 자재, 제조, 품질, 물류다.
- 품질 부서장은 IQC, LQC, OQC, 전진검수/FAT의 정·부 담당자를 모두 지정할 수 있다.
- 생산관리 부서장은 별도 축소 화면을 사용하지 않고 기존 `ProductionPlan.Update` 전체 수정 계약을 사용한다.
- 화면 숨김만으로 권한을 판단하지 않는다. 서버가 저장 시점마다 활성 사용자, 부서장 여부, 소속 부서와 전송한 책임 구분을 다시 확인한다.

## 3. 저장과 이력

- 부서장 전용 API는 자기 부서 책임 구분과 자기 부서의 활성 사용자만 반환한다.
- 자기 부서 외 책임 구분, 다른 부서 사용자, 비활성 사용자 지정은 거부한다.
- 담당자 row version을 사용해 동시 수정을 감지한다.
- 기존 담당자를 변경하거나 해제할 때는 현재 계약대로 수정사유를 필수로 받는다.
- 담당자 변경 전·후, 변경자, 변경시각과 수정사유는 기존 `ProjectAssignee` 감사이력에 남긴다.
- 저장 후 기존 `프로젝트 담당자로 지정되었습니다.` 인앱 알림과 생산계획 후속 업무 생성 규칙을 그대로 재실행한다.

## 4. 화면

- 프로젝트 상세 생산계획 영역은 활성 프로젝트이며 사용자가 전체 수정 권한 또는 부서장 전용 범위를 가진 경우에만 `생산계획 수정` 버튼을 표시한다.
- 생산관리 사용자는 현재 전체 수정 화면을 그대로 사용한다.
- 다른 부서장은 프로젝트 기본 식별 정보, 자기 부서명, 자기 부서 담당자 선택, 수정사유, 저장·취소만 본다.
- 다른 부서 담당자, 계획 항목, 날짜, 실적 연결, Excel, Item 설정은 렌더링하지 않는다.
- 기존 흑백 wireframe, 입력 section, action bar, 버튼과 카드 규격을 재사용한다. 새로운 강조선·컬러 강조 박스를 추가하지 않는다.
- 모바일 390px에서 가로 넘침 없이 한 열 입력으로 전환한다.

## 5. 프로젝트 생성 알림

- 기존 프로젝트 생성 알림은 활성 사용자 전체에게 그대로 발송한다.
- 같은 생성 event에서 지원 부서의 활성 부서장에게 `프로젝트 담당자를 지정해 주세요.` 알림을 추가한다.
- 생산관리 부서장은 기존 생산계획 업무가 이미 있으므로 이 추가 요청 대상에서 제외한다.
- 알림 링크는 해당 프로젝트의 생산계획 수정 route다. 로그인한 부서장에 따라 서버가 자기 부서 전용 화면을 결정한다.
- 추가 요청은 `WorkAssignment` 원본으로 저장해 인앱 알림, Teams 활동 알림과 인앱 연동 PWA 푸시 대상이 된다. 프로젝트 생성 전체 공지 메일을 중복 발송하지 않는다.
- 프로젝트 생성 재처리 시 idempotency key로 같은 요청 알림과 수신자를 중복 생성하지 않는다.

## 6. 포함·제외 범위

### 포함

- 부서장 자기 부서 담당자 조회·저장
- 생산관리 전체 화면과 부서장 축소 화면 분기
- 프로젝트 생성 시 부서장 담당자 지정 요청 알림
- Backend 권한·후보·동시성·감사이력·알림 집중 검증
- Frontend 분기·표시·저장·모바일 검증

### 제외

- 부서장이 생산계획 항목·기간·실적 연결을 수정하는 기능
- 부서장이 다른 부서 담당자를 조회·수정하는 기능
- 담당자 지정 요청을 별도 내 업무 상태로 만들거나 완료 처리하는 기능
- 새 메일 정책, 에스컬레이션, 재알림 주기
- DB migration, 운영 DB mutation, commit·push·merge·배포

## 7. 완료 기준

1. 생산관리 사용자는 기존 전체 생산계획 수정 기능을 그대로 사용할 수 있다.
2. 각 지원 부서장은 자기 부서 담당자만 보고 저장할 수 있다.
3. 일반 사용자와 다른 부서 값의 직접 요청은 서버가 403 또는 검증 오류로 차단한다.
4. 프로젝트 상세 조회는 역할과 관계없이 기존 읽기 권한 범위에서 전체 계획·담당자를 유지한다.
5. 프로젝트 생성 시 전체 생성 알림과 별도의 부서장 담당자 지정 요청 알림이 중복 없이 생성된다.
6. 부서장 저장 후 감사이력과 기존 담당자 지정 후속 알림이 유지된다.
7. PC와 390px 모바일 화면이 현재 디자인 규격을 따르고 가로 넘침이 없다.
