## 해결한 업무 문제

1. 일반 IQC 업무의 `상태` 열에 업무 상태가 아니라 긴급도가 표시되어 정상 검사도 `긴급`으로 보였다.
2. 내 업무의 이동 버튼 일부가 실제 처리 화면이 아닌 프로젝트 상세 첫 화면만 열었다.
3. Pending 생성 시 조치 담당자만 알림을 받아 생산관리·영업·품질이 중요한 중단 사실을 놓칠 수 있었다.
4. 전체 흐름 8단계의 명칭과 점등 조건이 실제 `생산관리 제조 요청` 및 자재 도착 흐름과 달랐다.
5. 생산계획 공통 코멘트가 입력 화면에는 있었지만 조회 위치와 업무 의미가 분명하지 않았다.

## 구현 결과

1. 내 업무의 `상태`와 `긴급도`를 분리했다.
   - 일반 IQC는 `시작 전` 등 실제 처리 상태로 표시한다.
   - 실제 Pending 재검사처럼 긴급 업무만 별도의 긴급도 표시를 유지한다.
2. 내 업무 이동을 저장된 정확한 업무 주소 기준으로 통일했다.
   - 자재 입고 확정, IQC·LQC·OQC·전진검수·FAT 재검사, 제조·물류 등 기존 업무가 해당 프로젝트·업무·도착분·패널을 직접 연다.
   - migration `0065`가 기존 미완료 업무의 일반 주소를 가능한 범위에서 정확한 주소로 멱등 보정한다.
3. Pending 알림 수신자를 확대했다.
   - 조치 정·부 담당자에게는 기존 실행 업무와 알림을 유지한다.
   - 생산관리 정·부, 영업 정·부, 관련 품질 정·부에는 중복 없는 참조 알림을 생성한다.
   - 재검사 불합격으로 다시 조치 요청이 된 경우에도 같은 수신자 기준을 적용한다.
   - 품질 부적합 Pending은 기존 긴급 알림 전달 계약을 그대로 사용하므로 실제 provider가 활성화된 운영 환경에서는 사용자 알림 설정과 발송 정책에 따라 Teams·메일 전달 대상으로 이어진다. 이번 실험에서는 실제 provider를 호출하지 않았다.
4. 프로젝트 전체 흐름 8단계를 `생산관리 / 제조 요청`으로 고쳤다.
   - 자재 도착 확정이 한 건이라도 생기면 생산관리 제조 투입 판단 업무와 자재 키팅 업무를 생성한다.
   - 키팅 완료 또는 생산관리 제조 요청 중 하나가 있으면 단계가 시작 또는 부분 완료로 집계된다.
   - 기존 누락 업무와 잘못된 단계 표시는 migration `0065`와 조회 시 파생 집계로 보정한다.
5. 생산계획의 `생산관리 공통 코멘트`를 `생산관리 전체 전달사항`으로 바꿨다.
   - 프로젝트 상세 생산관리 탭의 생산계획표 위에 값이 있을 때만 조회된다.
   - 계획 항목별 생산관리 코멘트는 별도 열로 그대로 유지한다.
