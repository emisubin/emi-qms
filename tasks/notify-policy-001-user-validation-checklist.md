## 자동 검증

- [x] 일반 업무, Pending, 프로젝트 lifecycle별 인앱·Teams Activity·메일 matrix가 분리된다.
- [x] 새 자동 TeamsChannel delivery가 생성되지 않고 과거 handler·이력 계약은 유지된다.
- [x] 제조 중단은 긴급 Pending 원본 한 건만 만든다.
- [x] Pending 종결은 등록 알림 수신자 snapshot을 사용하고 메일을 만들지 않는다.
- [x] 프로젝트 생성은 활성 사용자 전체, 납기·상태·17단계는 영업담당자+지정 담당자, 18단계는 영업부서 메일만 사용한다.
- [x] 담당자 미지정 시 활성 부서장 전원에게 공유되고 첫 처리자 한 명이 나머지를 자동 종료한다.
- [x] 활성 부서장 0명은 해당 부서를 표시한 409로 차단한다.
- [x] 패널별 업무 행은 유지하면서 같은 묶음 작업 알림은 중복 생성하지 않는다.
- [x] 생산계획·구매 일정 원본 변경은 미완료 업무 due date만 동기화한다.
- [x] 평일 Digest, 대한민국 휴일 제외, L0·L1만 신규 평가하는 정책이 적용된다.
- [x] PWA delivery는 실제 인앱 가시성과 여러 활성 기기 구독을 따른다.
- [x] Frontend 210/210과 production build가 통과했다.
- [x] Backend 전체 회귀 516/516이 최종 통과했다.
- [x] Isolated Full-Stack 2/2와 화면 폭 1440px·390px이 통과했다.

- [x] `내 알림 설정`에 사용자가 바꿀 수 있는 3개와 필수 2개만 보인다.
- [x] 안내문에 인앱과 필수 Pending·프로젝트 알림은 해제할 수 없다고 표시된다.
- [x] 일반 자동 업무 Teams, D-1 Teams, 평일 요약 메일을 각각 끄고 다시 켤 수 있다.
- [x] 긴급·차단과 L1은 `필수`로 표시되고 스위치가 없다.
- [x] 프로젝트 담당자를 비운 검수 데이터에서 같은 부서의 부서장 모두에게 `부서장 공유` 업무가 보인다.
- [x] 부서장 한 명이 완료하면 다른 부서장에게 `다른 부서장이 처리`로 보인다.
