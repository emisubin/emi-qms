## Round 4 기준선 확인

Round 3 답변 `1a`, `2b`, `3a`, `4a`를 누적 interview 문서와 실제 코드·양식 관리 구현에 다시 대조해 확인한 사실은 다음과 같다.

- 품질 domain **부서 양식 관리자 지정**(TASK-ADMIN-002)은 실제 양식 관리 구현에 존재하며, 답변 `1a`가 요구하는 "지정된 활성 품질 부서장" 식별 기준으로 그대로 재사용할 수 있다.
- 현재 구매품 구분 관리는 시스템 관리자 또는 품질부서 활성 사용자 전원이 변경할 수 있다. 답변 `1a`는 이 중 구분별 검사 스위치·방식·검사 항목 변경을 지정 부서장 기준으로 좁히는 결정이고, 답변 `2b`는 시스템 관리자의 쓰기 허용을 현행대로 유지하는 결정이다. 두 답변은 서로 모순되지 않으며 결합하면 쓰기 허용 대상은 **지정된 활성 품질 부서장 + 시스템 관리자**다.
- 현재 코드에서 `CategoryBased` 프로젝트는 구분의 검사 필요가 켜져 있으면 구분과 무관하게 항상 스캔형 검사로 생성된다. 답변 `3a`·`4a`와 Round 2 답변 1·2가 확정한 "구분별 스캔형/상세형 선택 + 구매품 저장 시점 방식 고정 + 회차 시작 시점 항목 고정" 계약은 이 분기를 확장하는 것으로 구현 가능하며 기존 계약과 충돌하지 않는다.
- 도착 등록·검사 생성이 같은 transaction에서 결정되고, 상세검사 항목이 검사 회차 생성 시점의 양식 version으로 고정되는 기존 구조는 답변 `4a`와 정확히 같은 형태다. 새 snapshot 구조를 만들 필요가 없다.

## 확인용 요약

- **해결할 문제**: 전역 IQC 양식 한 개와 `IQC 필요/없음` 이분 설정으로는 구매품 구분별로 다른 검사를 운영할 수 없고, 구분 수가 늘면 양식 관리에서 원하는 구분을 찾기 어렵다.
- **권장 범위**: 기존 양식 관리 안에서 구매품 구분을 검색·선택하고, 구분별 검사 스위치·검사 방식(스캔형/상세형)·상세 검사 항목을 관리하며, 저장된 설정을 구매품 snapshot과 도착분 검사 생성에 연결하는 기능. 새 검사 엔진은 만들지 않는다.
- **확정한 정책**:
  1. 검사 방식은 구분마다 부서장이 양식 관리에서 스캔형 또는 상세형(검사 항목 작성)을 선택한다. 스캔형을 외함 전용으로 고정하지 않는다. (Round 2 답변 1·2)
  2. 이번 작업은 기능 제공까지다. 초기 상태는 현재 동작 그대로(외함=스캔형 검사 켜짐, 판금류·부스바·명판·기타=검사 없음)이며, 실제 전환은 이후 품질팀이 화면에서 수행한다. (Round 2 답변 3)
  3. 이미 저장된 구매품에는 새 설정이 소급 적용되지 않는다. 구매품 저장(수정 저장 포함) 시점에 해당 구분의 검사 스위치가 켜져 있고 방식이 유효한 경우에만 도착분에 IQC를 생성한다. (Round 2 답변 4, Round 3 답변 `4a`)
  4. 상세형은 검사 항목이 1개 이상 저장된 뒤에만 스위치를 켤 수 있고, 활성 상태에서 항목 0개 저장을 차단한다. 스캔형은 항목 없이 스위치만으로 유효하다. 빈 양식 검사와 임의 전역 양식 fallback은 구조적으로 불가능하다. (Round 3 답변 `3a`)
  5. 검사 여부·방식은 구매품 저장 시점에 고정하고, 상세 검사 항목 내용은 도착분 검사 회차를 시작하는 시점의 해당 구분 현재 양식으로 고정하며 확정 후 불변이다. 같은 구매품의 회차별 양식 version을 표시한다. (Round 3 답변 `4a`)
  6. 구분별 검사 스위치·방식·검사 항목 변경은 기존 품질 domain **부서 양식 관리자 지정**을 받은 활성 부서장과 시스템 관리자만 수행한다. 시스템 관리자 쓰기 차단은 하지 않으며 "관리자 비관여"는 운영 관행으로 유지한다. (Round 3 답변 `1a`·`2b`)
  7. 파생 규칙: 기존 구분 관리 화면의 `IQC 필요` 토글은 새 구분별 검사 설정으로 대체하거나 같은 권한 규칙(지정 품질 부서장 + 시스템 관리자)으로 통일해 우회 경로를 없앤다.
  8. 검사 항목·사진·판정·PDF·부적합 Pending·재검사는 기존 상세 IQC 엔진을, 스캔본 등록·판정은 기존 외함 스캔형 엔진을 재사용한다. 전역 `MATERIAL_IQC` 양식은 legacy `AllReceipts` 프로젝트 전용으로 보존하고 화면에서 적용 대상을 혼동하지 않게 안내한다.
  9. 설정·양식 변경은 변경자·시각·이전/이후 값의 append-only 감사와 optimistic concurrency를 적용하고, 사용된 구분·양식·연결은 hard delete하지 않는다.
  10. UX는 기존 Graphite 양식 관리의 "대상 선택 → 현재 양식 관리" 패턴과 catalog·editor·badge·feedback을 재사용하고, 구분 수 증가에 대비한 검색·필터를 제공하며 desktop·390px을 검증한다.
