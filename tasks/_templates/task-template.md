# <Task/change — 사용자에게 생길 결과>

필요한 항목만 기존 Task에 사용한다. 이미 기록된 계약·상태를 새 파일에 복사하지 않는다. 실행·승인은 [Root](../../AGENTS.md), 검증은 [검증표](../../docs/development/validation-matrix.md)를 따른다.

## 목표와 경계

- 요청·유효 승인 출처와 해당 작업/대상/환경:
- 현재 사실, 변경 범위·담당 파일, 보존할 업무/데이터/권한 계약:
- 권장 접근과 사용자에게 보이는 완료 조건:

## 확인과 결과

- 필요한 테스트: 발동 입력 → 해당 경로 → 구현과 독립적인 기대 결과.
- 실제 변경·검증 근거: 코드 기준선, 명령/범위·환경, 결과 위치, 미실행 이유.
- 필요한 경우 독립 review: 기준선·실제 Finding·보정/재검토 결과.
- 상태: 구현 / 자동 검증 / 사용자 검수 / 원격 반영 / 배포를 구분.

## 남은 일과 재개

- 미해결 문제·후속 항목·다음 행동·필요한 결정:
- 진행 중 session/자원이 있을 때 목적·소유·source·보존/정리 경계:

사용자 동작이 바뀌면 안내·검수 항목을 여기에 추가하고, 반복 운영 절차가 바뀔 때만 해당 SOP를 갱신한다.
