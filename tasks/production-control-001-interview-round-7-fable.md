### 질문 1 — 선택지 5-B의 정확한 의미: 기존 프로젝트가 쓸 화면

**왜 필요한가요:** Round 6 질문 5의 선택지 B는 "**기존 프로젝트는 지금 화면(단일 예정일 + 체크 캘린더)을 그대로 유지**하고, 새 프로젝트만 새 계획·실적 표와 가로 막대 일정 화면을 쓴다"는 뜻이었습니다. 그런데 `5-B`를 선택하시면서 함께 적어 주신 설명은 "**양식이 바뀌어도 이미 생성된 프로젝트는 생성 당시 양식을 계속 사용하고, 새 버전은 이후 생성 프로젝트부터 적용**"이었습니다. 이 설명은 화면 선택이 아니라 **양식 복사본(snapshot) 원칙**에 대한 것이고, 이 원칙은 A를 골라도 B를 골라도 똑같이 보장됩니다. 그래서 "기존 프로젝트는 옛 화면을 유지한다"까지 의도하신 것인지, 아니면 snapshot 원칙을 확인해 주신 것인지 구분이 필요합니다.
**답이 바꾸는 범위:** 기존 프로젝트의 화면 동작, 기존 단일 예정일을 계획 시작·종료로 복사하는 Round 2 결정의 적용 대상, 유지보수할 화면의 수.

- **A. 화면은 하나로 통일한다(snapshot 원칙 확인이었던 경우).** 기존 프로젝트도 새 계획·실적 표와 가로 막대 일정 화면을 사용한다. 다만 자동 연결은 하지 않아 기존 항목은 "연결 안 됨"으로 표시되고, 담당자가 프로젝트 안 연결 수정으로 직접 연결한 항목부터 자동 실적이 표시된다. 기존 단일 예정일은 Round 2 결정대로 계획 시작일·종료일 같은 날짜로 복사하고 원본은 보존한다. 양식 snapshot 원칙("기존 프로젝트는 생성 당시 양식 유지, 새 버전은 새 프로젝트부터")은 그대로 지켜진다.
  - 장점: 화면이 하나라 유지보수가 단순하고, 진행 중인 프로젝트도 계획 기간 입력과 일정 비교를 바로 쓸 수 있습니다. 잘못된 자동 연결은 없습니다.
  - 단점: 기존 프로젝트를 열면 처음에는 "연결 안 됨" 항목이 많이 보이며, 필요한 프로젝트만 골라 담당자가 직접 연결해야 합니다.
- **B. 문자 그대로 기존 프로젝트는 옛 화면을 유지한다.** 기존 프로젝트는 단일 예정일 + 체크 캘린더 화면을 계속 쓰고, 이 기능 이후에 생성되는 프로젝트만 새 화면을 쓴다. 이 경우 기존 단일 예정일을 계획 시작·종료로 복사하는 작업(Round 2 결정 4)과 기존 데이터 이전은 기존 프로젝트에 적용하지 않는 것으로 정리됩니다.
  - 장점: 기존 프로젝트 데이터와 화면을 전혀 건드리지 않아 이전 위험이 없습니다.
  - 단점: 두 화면을 계속 함께 유지보수해야 하고, 지금 진행 중인 프로젝트는 계획 기간·자동 실적·가로 막대 일정을 쓸 수 없습니다.

**권장: A.** 적어 주신 설명(생성 당시 양식 유지)은 A에서도 완전히 보장되며, 진행 중인 프로젝트가 새 기능의 가장 큰 수혜 대상이기 때문입니다. 다만 "기존 프로젝트는 정말 건드리지 않겠다"가 의도였다면 B로 확정해 주시면 됩니다.

### 질문 2 — 구매·자재·품질·물류 연결 대상: 고정 사건 목록에서 선택하는 방식 확인

**왜 필요한가요:** Round 6 질문 3에 함께 드린 확인 요청("제조 단계만 자유 구성 목록이고, 나머지 부서는 시스템이 이미 확정 처리하는 사건 목록에서 고른다")에 별도 답변이 기록되지 않았습니다. 이 방식이 확정되어야 양식 관리 화면의 연결 구성 UI와 자동 실적 계산 근거를 정할 수 있습니다.
**답이 바꾸는 범위:** 양식 관리의 실적 연결 구성 화면, 자동 실적 계산의 근거 데이터 종류.

- **A. 고정 사건 목록에서 선택한다(권장드린 이해가 맞는 경우).** 생산계획 항목의 연결 대상 중 제조는 관리자가 구성한 제조 항목 목록에서, 구매·자재·품질·물류는 시스템이 이미 확정 처리하는 사건 목록 — 예: 발주 완료, 전체 입고 확정, IQC 합격, LQC 합격, OQC 합격, 전진검수 합격, FAT 합격, 포장 완료, 출발 처리, 납품 완료 — 에서 고른다.
  - 장점: 각 사건이 부서 담당자의 확정 행위와 1:1로 대응하므로 자동 실적이 틀릴 여지가 없고, 연결 구성 화면이 단순합니다.
  - 단점: 목록에 없는 새로운 사건이 필요해지면 시스템 수정이 필요합니다(현재 확정 처리되는 사건은 위 목록으로 전부 포함됩니다).
- **B. 다른 부서 항목도 제조처럼 자유 구성 목록으로 만든다.**
  - 장점: 부서별 항목 이름을 자유롭게 붙일 수 있습니다.
  - 단점: 자유롭게 만든 항목은 부서 업무 화면에 대응하는 확정 행위가 없어 자동 실적을 계산할 근거가 없고, 결국 수동 입력 항목이 되어 "부서 실데이터 기반 자동 실적"이라는 이번 Task의 목표와 어긋납니다. 범위도 크게 늘어납니다.

**권장: A.** 자동 실적은 각 부서의 실제 확정 행위에서만 파생된다는 이번 Task의 핵심 원칙과 일치하는 방식은 A뿐입니다.
