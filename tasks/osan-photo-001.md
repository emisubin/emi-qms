## 범위와 선행조건

PROGRESS-001의 프로젝트·수량 대상·7단계 식별과 완료 계약을 선행조건으로 한다. 사진 저장 설계는 진행 구현과 함께 준비할 수 있지만 전체 완료 흐름 연결은 그 계약을 기준으로 한다.

1. 완료 팝업에서 모바일 카메라 촬영 또는 기존 이미지 선택, 저장 전 미리보기와 잘못 고른 사진 제거/재선택.
2. 사진 데이터와 프로젝트·대상·단계·등록자·등록 시각을 연결하여 영구 보존. 오산 DB에 연결 정보와 기록을 저장한다. 원본을 DB에 넣는 방식과 파일 저장소에 두는 방식은 기존 저장 구조·용량·백업 영향을 대조해 명시적으로 확정한다. 임시 미리보기 URL만 저장하고 영구 저장 완료라고 하지 않는다.
3. 완료 후 해당 대상·단계의 사진, 실제 작업자와 완료 일시 조회. 재접속·다른 기기에서도 동일 기록을 조회하고 다른 대상/단계의 사진이 섞이지 않게 한다.
4. 개별/전체 선택 완료와 연결한다. 일괄 적용 사진의 대상 범위를 저장 전 안내하고 사진과 각 대상의 연결을 보존한다.
5. 저장 중 중복 제출 방지, 실패 안내와 재시도. 선택한 사진 저장이 실패하면 성공/완료로 표시하지 않는다. 재시도·경쟁 요청이 사진이나 완료 이력을 중복 생성하지 않도록 한다.

## 계획 기본안·확정할 세부사항

- 직전 권장안을 수용한 사용자 응답에 따라 사진은 선택 첨부, 여러 장 허용, 일괄 선택 시 동일 사진 적용 안내를 기본안으로 한다. 저장 후 수정·삭제 및 완료 취소/재개는 첫 범위에 포함하지 않는다. 저장 전 재선택과 저장 후 기록 정정은 구분한다.
- 구현 설계에서 이미지 형식·장수·개별/총 용량·모바일 압축, 원본 저장 위치, 보존·백업 및 실패 시 미연결 사진 처리 방법을 기록한다. 기존 계약으로 결정할 수 있으면 권장안을 채택하고 비용·권한·외부 자원 변경만 별도 판단한다.
- 단계 설명용 안내 사진은 PROGRESS-001 소유이며 이 Task의 완료 증빙과 혼합하지 않는다.
- 프로젝트 실데이터, Directory/청주/오산 DB 경계와 기존 서버 권한을 보존한다. 사진 조회/등록에도 사업부·프로젝트 권한을 검사하고 공개 URL로 우회 노출하지 않는다.
- 포장 선행조건과 마지막 대상 포장 시 프로젝트 자동 완료를 보존한다. 사진 처리 중 오류가 불완전한 완료 상태를 만들지 않도록 진행 Task와 저장 경계를 함께 설계한다.

## 완료 조건·검증

- 촬영/첨부 → 미리보기 → 저장 → 완료 화면 → 재접속 조회를 모바일에서 실제 확인한다. 기기 카메라 미검증은 별도 표시한다.
- 사진 없는 완료와 여러 사진 첨부, 잘못된 형식/크기, 권한 거부, 타 사업부 접근, 저장 실패·재시도·중복 요청, 일괄 대상 연결을 직접 대응하는 테스트로 확인한다.
- 사진 저장 구조가 확정되면 전용 disposable DB/storage에서 migration·기존 데이터 보존 및 조회를 검증한다. 운영 DB나 실제 provider를 일반 테스트에 사용하지 않는다.
- 지정 Figma 팝업·선택창·완료 후 화면과 동일 조건에서 육안 비교한다. 제품 구현 후 필요한 독립 검토를 수행하고 증거는 기존 완료 정책을 따른다.
- 전체 회귀는 VALIDATION-001의 사용자 검수 후 최종 후보 실행에 합친다. 개별 기능 검증을 생략하는 뜻이 아니다.

현재는 문서만 작성·검토했다. 제품 코드·DB·runtime 변경, 자동 제품 테스트, 사용자 검수, push·merge·배포는 수행하지 않았다.
