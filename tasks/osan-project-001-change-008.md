- 관리자 메뉴는 청주 관리·오산 관리로 구분한다. 양쪽 관리자 및 총괄 관리자는 두 관리 범위에 접근할 수 있다. 관리 대상 캠퍼스를 명확히 표시하며, 관리 메뉴 전환이 본인 소속 변경을 뜻하지 않는다. 관리자 권한 설정은 박수빈에게만 제공한다. 구체적인 화면 디자인은 별도 기획 단계에서 확정한다.
- 최초 운영 전환 시 기존 관리자 계정을 모두 총괄 관리자로 전환하고 사용자가 이후 정리한다. 적용 전 실제 전환 대상 계정 목록을 확인·제시한다. 이번에는 전환하지 않는다.
- 개발·디버깅 기간에는 총괄 관리자가 청주·오산 관리자에게 가는 모든 인앱·메일 알림을 수신한다. 같은 사건의 수신 대상이 겹쳐도 중복 발송하지 않는다. 향후 전체 알림 수신 해제가 가능하도록 관리자 권한과 별도 구분한다.

현재 상태: 정책 1 확정·문서 정합성 확인 완료. 다음 기획은 단계 상태·반려·수정 승인·초기화의 처리 규칙이다. 사용자와 필요한 양식을 모두 확정한 후 구현으로 진행한다.

### 후속 기획 2 — 단계 상태·반려·수정 승인·초기화 확정 (2026-09-11)

사용자의 후속 답변으로 아래 처리 규칙을 확정한다. 앞의 배포 구현과 구분되는 기획 계약이며 제품 구현·운영 변경은 아직 하지 않는다.

- 완료된 대상·단계는 각각 독립된 건으로 관리한다. 앞 단계가 반려되어도 이미 완료된 후속 단계의 기록과 완료 상태를 유지하며, 앞·뒤 단계 각각의 반려 재등록 또는 수정 승인 조건에 따라 둘 다 수정할 수 있다. 최초 미완료 단계의 신규 완료에는 기존 선행 단계 완료 조건을 유지한다.
- 반려·초기화는 담당 캠퍼스 관리자 또는 총괄 관리자만 가능하며 사유를 입력한다. 선택한 대상·단계만 되돌리고 기존 사진·코멘트·처리 이력을 보존한다. 반려 또는 수정 승인으로 열린 단계는 해당 프로젝트의 진행 등록 권한이 있는 누구나 1회 저장할 수 있고 저장 후 다시 잠긴다.
- 수정 승인 상태에서는 수정과 관리자 초기화가 가능하고 반려는 불가능하다. 일반 등록자는 수정만, 관리자에게는 초기화도 표시한다. 동일 제한을 서버에서 적용한다. 초기화 시 기존 수정 승인을 종료하며, 초기화 전에 열린 수정 화면이나 승인을 사용한 저장은 거부하고 최신 상태를 다시 확인하도록 한다. 앞서 제안한 ‘수정 승인 중 초기화도 불가’ 기준은 이 사용자 결정으로 대체한다.
- 반려 알림은 해당 대상·단계의 최초 등록자 및 이후 사진·코멘트 수정 등록자 모두에게 인앱·메일로 보낸다. 같은 사용자는 한 번만 수신한다. 관리자 승인·반려 처리만 하고 완료/수정 데이터를 등록하지 않은 사람을 이 등록자 집합에 자동 포함하지 않는다.
- 프로젝트 완료 알림은 해당 프로젝트의 최초 완료 시 한 번만 보낸다. 반려·초기화 후 재완료되더라도 프로젝트 완료 알림은 다시 보내지 않는다. 재등록 시 단계 완료·수정 완료 알림은 기존 확정 대상에게 계속 발송한다. 초기화는 알림 없이 담당자·시각·사유와 이전 기록을 이력에 남긴다.
- 반려·초기화 시 해당 단계와 프로젝트 진행률/상태를 다시 계산한다. 완료 프로젝트에 미완료 단계가 생기면 진행 중으로 전환하고 모든 대상의 7단계가 다시 완료되면 자동 완료한다. 재완료 알림 금지 여부와 프로젝트 완료 상태 계산은 별개다.

현재 상태: 기획 1·2 확정. 다음은 사진·코멘트 입력 기준 및 현재 기록/이력의 표시 기준 확정이다. 이후 화면·인앱·메일 시안과 발송 규칙을 모두 정한 뒤 구현한다.

### 후속 기획 3 — 사진·코멘트·현재 기록·이력 확정 (2026-09-11)

사용자 답변으로 아래 입력·표시 기준을 확정한다. 제품 변경은 화면·알림·메일 등 사전 기획을 마친 뒤 진행한다.

- 대상·단계의 완료 및 수정 저장에는 사진이 필수이며 최종 사진 묶음은 최소 1장, 최대 10장이다. 수정할 때 유지한 기존 사진과 새로 추가한 사진을 합산한다. 이전의 선택 첨부 및 최대 5장 기준은 향후 구현에서 이 기준으로 대체한다. 기존 사진 없는 과거 완료 기록은 보존하며 소급 변경하지 않는다.
- 코멘트는 선택 입력으로 0~1000자이며 수정할 수 있다. 사진만 저장할 수 있지만 코멘트만으로 사진 없는 완료·수정 저장은 할 수 없다.
- 수정 시 기존 사진을 유지하면서 일부 제외하거나 새 사진을 추가할 수 있다. 제외·교체 전 사진과 이전 코멘트는 해당 저장 이력에 보존한다. 수정 가능 여부와 1회 저장 후 잠금은 기획 2의 권한·상태 계약을 따른다.
- 현재 기록에는 최종 저장된 사진·코멘트와 해당 저장의 최종 등록자·시간을 함께 표시한다. 기존 사진을 유지한 코멘트 수정도 새 저장 건이며, 최초 완료자의 이름·시간을 최신 기록의 등록 정보로 계속 표시하지 않는다.
- 이력은 저장 건마다 당시 사진·코멘트·등록자·시간을 묶어 조회한다. 반려·승인·초기화 기록도 시간순으로 함께 조회하며 각각 처리한 사용자·시간과 해당 사유를 표시한다. 과거 저장 묶음은 이후 편집으로 덮어쓰지 않는다.
- 사진 장수는 10장으로 확정했다. 현재 서버의 장당 5MiB·전체 15MiB 제한과 형식/모바일 처리 기준은 장수 변경과 별개이며 이번 답변을 용량 확대 승인으로 해석하지 않는다. 용량 기준 변경 필요 여부는 구현 전에 정리한다.

현재 상태: 기획 1·2·3 정책 확정 및 문서 정합성 확인. 다음은 PC·모바일·태블릿의 단계 입력/상세/이력과 관리자 화면 디자인이며, 인앱 알림·메일 양식 및 남은 세부 기준까지 확정한 뒤 구현한다. 이번 변경은 문서만이며 제품 코드·운영 DB·발송·원격 반영·배포는 변경하지 않았다.

### 후속 기획 4 — 단계 화면 시안 확정 (2026-09-11)

사용자는 사진 영역을 확대한 3차 시안(http://127.0.0.1:5203/?revision=3)을 확정했다. [승인 시안 보존본](../docs/design/osan-stage-review/revision-3.html)을 단계 상세·등록/수정·이력 화면의 구현 기준으로 사용한다. 캠퍼스 관리자 화면은 이번 확정 범위에 포함되지 않는다.

- 실제 사이트의 공통 스타일·EMI 로고·왼쪽 메뉴·7단계 카드와 연결한다. 모바일은 기존 로고와 좌우 단계 이동을 이어간다.
- PC 상세는 왼쪽 단계 설명, 오른쪽 큰 사진 영역으로 배치한다. 기본 현재 기록 화면은 세로 스크롤 없이 표시하고 사진 선택 및 코멘트를 함께 제공한다. 긴 코멘트 전체 보기와 누적 이력은 별도 보기로 제공한다.
- 모바일도 사진 기본 표시 크기를 확대한다. 사진 클릭 시 화면을 채우는 확대 보기를 열고 확대 상태에서 이전·다음 사진을 전환한다. 실제 사진은 원본 비율과 색상을 보존한다.
- 최종 저장 기록과 저장·반려·승인·초기화 이력 및 상태별 버튼은 기획 1~3의 확정 계약을 따른다. 시안의 예시 데이터·일러스트·역할/상태 전환 도구·가상 저장 동작은 제품 기능이 아니다.
- 시안 확인: 1366×768 PC 현재 기록에서 본문 높이와 내용 높이 일치(490px), 사진 높이 337px; 확대 열기·닫기 및 사진 전환 버튼 확인. 앞 시안에서 PC·모바일 배치를 직접 확인했고, 실제 제품 구현 후 화면 폭·상태별 검증은 별도로 수행한다.

현재 상태: 단계 화면 시안 사용자 확정. 다음은 캠퍼스별 관리자 메뉴 시안이며 이후 인앱 알림·메일 양식과 남은 세부 기준을 정한다. 이번에는 승인 시안과 기획 기록만 보존하며 제품 구현·운영 변경·원격 반영·공개배포는 하지 않는다.
