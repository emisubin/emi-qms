## 3. 부서별 평가

### 영업

1. **KPI 활용성 — 부분 유용:** 완료 매출 4.8억 원이 7월 막대로 즉시 반영돼 결과 확인은 쉽다. 하지만 월 목표가 미등록이면 목표 달성률·잔여 목표가 모두 비어 실적 막대 하나만 남는다. 목표 등록 유도와 미등록 원인 바로가기가 필요하다.
2. **추가되면 좋은 기능:** 영업 Home에서 진행 중 프로젝트의 `사급 지연`, `열린 Pending`, `납품 예정 초과`, `회계 요청 대기`를 금액 기준으로 함께 보여주면 매출 위험을 먼저 판단할 수 있다. 현재 연간 확정 매출은 사후 지표에 가깝다.
3. **UI/UX 위치:** 프로젝트 상세 상단의 큰 기본정보 9칸과 `다음 확인 대상`이 탭 본문을 아래로 민다. 영업이 자주 보는 납품·정산·회계 발행요청은 compact 요약 또는 sticky next-action으로 올리는 편이 낫다.
4. **없어져도 되는 요소:** 완료 프로젝트에서 `내 업무`와 `Pending` 빈 패널을 크게 유지할 필요는 적다. 빈 상태는 한 줄로 축약하고 최근 회계 발행요청 자료와 완료 매출을 우선하는 편이 낫다.

### 생산관리

1. **KPI 활용성 — 불일치:** 제조 Pending 6건이 생겼는데 부서 핵심 KPI는 `계획 미등록 2 / 작성 중 0 / 담당 미지정 2`를 계속 보여준다. 실제 당일 병목은 아래 `Pending`과 `내 업무`에서만 보이므로 `열린 제조 중단`, `차단 면수`, `최장 경과시간`을 부서 KPI로 올려야 한다.
2. **좋은 점:** Pending 6건이 내 업무의 시작 전·차단과 Issue Control의 Open·긴급에 같은 수로 반영돼 책임자가 놓치기 어렵다. 프로젝트 항목도 `open Pending 6건`을 우선 안내했다.
3. **입력 불편:** 12면 프로젝트라도 부서별 정·부 담당자와 품질 4단계 담당자를 한 번에 모두 지정해야 한다. 조직 기본 담당자 template, 최근 프로젝트 복사, 역할별 일괄 지정이 있으면 초기 입력 부담이 크게 줄어든다.
4. **UI/UX 위치:** 핵심 KPI와 Pending 카드가 분리돼 시선이 두 번 이동한다. 핵심 KPI에 병목을 포함하고 세부 Pending 목록으로 drill-down하는 한 경로가 더 자연스럽다.

### 설계

1. **KPI 활용성 — 유용:** 입력 전 `도면 미완료 프로젝트/패널`이 12면을 정확히 드러내 backlog 크기 판단에 도움이 된다. 다면 프로젝트에서는 프로젝트 수보다 패널 수가 더 실용적이다.
2. **입력 불편:** 패널명과 W/H/D를 12번 반복 입력해야 한다. `P01~P12 자동 번호`, 이전 행 복제, 다중 행 paste, 동일 치수 일괄 적용이 필요하다.
3. **추가되면 좋은 기능:** 입력 중 누락·중복 패널명·이상 치수를 실시간으로 요약하고 저장 전에 `12/12 완료`를 보여주면 긴 표에서 오류를 찾기 쉽다.
4. **없어져도 되는 요소:** 편집 중에는 QR·완료 상태처럼 입력과 직접 관계없는 열을 접고 이름·치수에 폭을 배정하는 compact edit mode가 낫다.

### 구매

1. **KPI 활용성 — 부분 유용:** 혼합 품목 2종을 입고 예정·지연 2건으로 즉시 보여주는 것은 좋다. 다만 일반 구매 지연과 고객 사급 지연은 책임 주체가 달라 `구매처 지연`과 `고객 제공 지연`으로 분리해야 행동이 명확해진다.
2. **확인된 결함:** 초기 데이터 load가 끝나기 전 `행 추가`가 활성화돼 있어 빠르게 입력하면 추가 행이 사라질 수 있었다. load 중 편집 잠금이나 skeleton이 필요하다.
3. **UI/UX 위치:** 공급 유형이 넓은 행 안에서 품목·수량·예정일과 나란히 섞여 있다. `일반 구매/사급`을 행 앞쪽의 강한 badge로 두고 발주·제공 책임과 지연 사유를 한 묶음으로 보여주는 편이 낫다.
4. **추가되면 좋은 기능:** 사급 예정일 변경 이력, 고객 독촉 기록, 다음 확인 예정일과 담당자를 구매 단계에서 넘기면 자재가 별도 메모 없이 이어서 추적할 수 있다.

### 자재

1. **좋은 점:** 사급 카드에서 예정 12 EA, 누적 6 EA, 미도착 6 EA, 처리 대기 0 EA와 7/15~17 도착 회차가 한 화면에 보여 분할 입고 추적 자체는 이해하기 쉽다.
2. **KPI 활용성 — 심각한 누락:** 사급 잔량 6 EA와 `제공 지연` badge가 있는데 상단 `도착 등록 대기/IQC 대기/부적합 차단/확정 대기`는 모두 0이다. Home KPI도 같은 위험을 보여주지 않아 정상처럼 오해할 수 있다.
3. **알림 결함:** 사급 예정일 초과 전용 알림은 0건이었다. 예정일 전 사전 알림, 당일 미입고, 초과 경과, 부분 입고 후 잔량을 자재 정·부 담당자에게 중복 없이 보내야 한다.
4. **입력 불편:** 6회 분할 입고마다 도착 등록→IQC 판정→입고 확정을 반복한다. 회차 timeline은 유지하되, 여러 회차의 IQC 요청·합격 확인을 연속 처리하는 queue와 `다음 입고 회차` 이동이 필요하다.
5. **UI/UX 위치:** 상단 숫자 KPI보다 `사급 1 · 제공 지연 1`이 더 중요한데 작은 우측 문구에 머문다. 클릭 가능한 위험 KPI로 올리고 사급 filter를 자동 적용해야 한다.

### 제조

1. **KPI 활용성 — 유용:** 12면 중 진행 6·차단 6이 핵심 KPI에 정확히 나타나 현장 상태를 빠르게 이해할 수 있었다.
2. **확인된 결함:** 한 패널에서 제조 4단계를 너무 빠르게 연속 확정하면 저장 하나가 누락돼 3/4 상태에 머물 수 있었다. 단계 저장 중 다음 버튼 잠금, 완료 toast, server version 확인이 필요하다.
3. **입력 불편:** 12면을 탭으로 오가며 동일한 4단계를 반복하는 비용이 크다. QR scan 후 해당 패널 자동 선택, `다음 미완료 패널`, batch queue, 키보드/스캐너 친화 동선이 필요하다.
4. **추가되면 좋은 KPI:** 패널당 목표 3일과 실제 소요, Pending 제외 순수 작업시간, 차단시간, 오늘 완료 면수를 보여줘야 공정 개선에 쓸 수 있다. 현재 대기/진행/차단은 순간 상태만 보여준다.

### 품질

1. **KPI 활용성 — 유용:** LQC 진입 직후 검사 대기 12와 내 업무 12가 일치해 backlog를 파악하기 좋다.
2. **입력 불편:** LQC·제조확인·OQC·전진검수·FAT 중 적용 단계까지 패널별로 반복하면 이번 시나리오에서 48개 검사 form을 처리해야 했다. 단계 구분은 필요하지만 판정 후 `다음 패널` CTA와 공통 증빙 재사용이 부족하다.
3. **추가되면 좋은 기능:** 같은 lot·프로젝트에서 공통 성적서 metadata와 사진을 여러 패널에 연결하되, 판정과 checklist 응답은 패널·단계별 audit로 유지하는 방식이 적절하다.
4. **KPI 개선:** 누적 `판정 완료`보다 오늘 검사 수, 1차 합격률, 재검·조치 평균 경과, 오래된 대기 건이 실무 개선에 더 유용하다. 기간 filter도 필요하다.

### 물류

1. **KPI 활용성 — 유용:** 품질 완료 직후 포장 대기 12가 정확히 나타나 인계 확인이 쉽다. 다만 납기 임박·초과 정보가 없어 우선순위 판단은 어렵다.
2. **입력 불편:** 12면 선택과 증빙 첨부를 한 프로젝트 단위로 처리할 수는 있지만, 카드 선택·Excel 선택·단계 실행 선택의 checkbox 의미가 비슷해 혼동할 수 있다. `이번 출하 구성 선택`이라는 단일 명칭과 선택 요약이 필요하다.
3. **UI/UX 위치:** 선택 대상이 길어지면 화면 하단 실행 버튼과 증빙 입력이 멀어진다. 선택 면수·단계·필수 증빙·실행 버튼을 sticky action bar로 유지하는 편이 안전하다.
4. **추가되면 좋은 KPI:** `오늘 출하`, `납기 초과`, `증빙 누락`, `고객 인수 확인 대기`를 넣고 포장/출발/배송 수량은 drill-down 세부값으로 두는 편이 더 행동 지향적이다.

## 4. 종합 우선순위

1. **P1:** 사급 예정일 초과 알림과 단계적 escalation을 추가한다. 사용자에게 화면 상시 감시를 요구하는 현재 방식은 실제 지연 관리 목적을 충족하지 못한다.

3. **P2:** 구매 초기 load 중 편집을 잠그고 제조 단계 저장을 직렬화한다.
4. **P2:** 생산관리 KPI를 계획 등록 상태만이 아니라 열린 Pending·차단 면수 중심으로 보강한다.
