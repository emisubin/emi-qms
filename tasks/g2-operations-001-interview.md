## 3. 정상·예외·복구 흐름

- 정상 흐름: 날짜별 오전조·오후조 생산 대수, 일일 납품 대수와 재고수량을 담당자가 입력한다. 출근 관리에서는 오전·오후 각각 EMI 직원·도급 직원 수를 입력한다. G2 홈에서 이번 달 생산·납품·재고와 재고목표, 오전조·오후조 생산량과 일 생산목표, 제조 인원 출근 현황을 확인한다.
- validation 실패: 미확정.
- 동시 처리·중복: 오전·오후 담당자의 분리 입력과 한 사용자의 일괄 입력을 모두 허용한다. 권한은 개인별로 나누지 않고 담당 부서 단위로 적용한다. 같은 날짜를 동시에 수정할 때의 충돌 처리는 미확정이다.
- 취소·재시도·복구: 미확정.
- 부분 실패와 rollback: 미확정.

## 4. Data·integration·lifecycle

- 신규 또는 기존 data 개념: 기존 PMS 데이터와 연결하지 않는 G2 일별 오전조·오후조 생산, 일일 납품·재고수량, 단일 일 생산목표·재고목표와 오전·오후별 EMI·도급 제조 출근 기록.
- 상태 전이: 과거·현재 값과 미래 예상치를 모두 허용한다. 미래 예상치는 해당 날짜의 실제 생산량으로 교체하고 이전 예상값은 별도로 보존하지 않는다. 재고는 생산·납품을 이용해 자동 계산하며 실사값이 있는 날짜부터 계산 기준을 다시 잡는다. 과거 생산·납품 정정은 다음 실사값 전까지만 재계산하고 실사 확정값을 보존한다. 생산·재고 목표는 적용 시작일별 변경 이력을 보존한다.
- 보존·감사·삭제: 정정 시 최종값과 마지막 수정자·수정 시각만 보존한다. 삭제 요구는 미확정이다.
- attachment·Excel·PDF: 미확정.
- 외부 연동·notification: 사용자가 다른 데이터와 연결하지 않는 독립 기능이라고 명시했다. 추가 외부 연동·알림 요구는 미확정이다.
- migration·기존 데이터: 신규 독립 데이터이며 기존 데이터 migration 요구는 없다. 과거·미래 날짜는 제한 없이 수기 입력할 수 있다.

## 5. UX와 운영 적용

- 진입 화면과 핵심 행동: 왼쪽 `G2` 부모 메뉴 아래 `홈`, `생산/출하 관리`, `제조 인원 출근 관리` 세 화면. 홈은 이번 달 기준으로 `생산·납품 막대 + 자동 재고 선 + 적용일별 재고목표선` 그래프, `오전조·오후조 누적 막대 + 적용일별 일 생산목표선` 그래프와 오전·오후별 EMI·도급 제조 인원 출근 현황표를 표시한다. 권한이 있는 사용자는 홈 재고 그래프에서 간헐적인 실사값을 입력·수정하며 실사 지점은 명시적으로 표시한다.
- loading·empty·error·success feedback: Repository 공통 UX를 적용하되 구체 문구와 저장 방식은 미확정이다.
- 접근성·390px·Teams narrow: 기존 데스크톱·모바일 공용 navigation과 390px page overflow 0 계약을 보존한다.
- UAT와 rollout: 원격 `main` 기반 isolated 구현·검증 후 사용자 검수, 게시·운영 적용은 별도 승인.
- rollback과 운영자 대응: 미확정.

## 8. Fable 확인용 요약

- 해결할 문제: 독립 G2 일일 생산·출하·제조 출근 수치의 입력·관리·통합 가시성 제공.
- 권장 범위: 세 G2 화면, 담당자별 분리·일괄 입력, 제한 없는 날짜와 미래 예상치, 자동 재고·홈 그래프 실사 보정, 적용일별 일 생산목표·재고목표, 이번 달 홈 요약.
- 확정한 정책: 기존 PMS 데이터와 연결하지 않는 독립 기능, G2 아래 세 화면, QMS Slice 1과 병렬 기획, 전체 조회·담당 부서 쓰기, 부서별 입력 범위, 최종값 중심 정정, 과거·미래 입력 허용, 고정된 오전조·오후조 생산과 오전·오후별 EMI·도급 출근 인원, 자동 재고·홈 그래프 실사 보정, 빈 값 0 계산, 미래 예상 재고, 목표 변경 이력, 홈 그래프 두 개와 출근 일별 표.
- 명시적 제외: 기존 데이터 연결과 현재 단계의 제품 구현·운영 적용·Git 게시, 영업팀 전용 손익관리 구현.
- Deferred 비차단 결정: `손익관리`는 향후 별도 신규 기능으로 추적하고, 구현 시 영업팀에만 노출한다.
