# TASK-AZURE-PILOT-001 User Manual

## 1. 이번 변경의 의미

운영 서비스를 실제로 고르기 전에, 잘못된 로그인 설정이나 database 업데이트 순서 때문에 공개 서비스가 시작되는 위험을 줄였다.

화면 기능과 업무 입력 방법은 바뀌지 않는다.

## 2. Microsoft 365 로그인 준비

운영에서는 Microsoft 365용 설정을 두 개로 나눈다.

- 화면용 앱: 사용자가 로그인하고 돌아올 공개 주소를 담당
- API용 앱: 로그인한 사용자가 업무 API를 호출할 권한을 담당

두 설정이 같거나 API 권한 주소가 잘못되면 배포 전 검사가 실패하도록 했다. 실패를 건너뛰지 말고 운영 담당자에게 알려야 한다.

## 3. Database 업데이트 방식

새 버전을 켜기 전에 database 구조 업데이트를 한 번 먼저 실행한다.

- 성공: 새 버전을 켤 수 있음
- 실패: 새 버전을 켜지 않고 원인을 수정
- 같은 명령을 다시 실행: 이미 완료된 항목은 중복 처리하지 않음

업데이트 중 다른 사용자가 동시에 같은 명령을 실행해도 한 번씩 순서대로 처리된다.

## 4. 일반 사용자가 확인할 사항

실제 공개 주소가 생긴 뒤 다음을 확인한다.

1. 회사 Microsoft 365 계정으로 로그인한다.
2. 본인의 사진·부서·이름과 메뉴가 정상인지 확인한다.
3. 본인 부서의 프로젝트 목록, 내 업무와 알림을 확인한다.
4. 권한이 있는 테스트 자료 한 건을 저장하고 다시 조회한다.
5. 로그아웃 뒤 뒤로 가기에서 이전 업무 내용이 다시 보이지 않는지 확인한다.
6. 문제가 있으면 화면에 실제 고객·사용자 정보가 보이는 screenshot 대신 발생 시각과 화면 이름만 전달한다.

## 5. 이번 단계에서 확인할 수 없는 것

아직 Azure hosting, domain, managed DB, WAF와 SIEM을 선택하지 않았기 때문에 실제 공개 주소는 없다. 따라서 다음은 서비스 선정 후 검수한다.

- 외부 HTTPS 접속
- 실제 운영 Microsoft 365 redirect
- 운영 DB backup/restore
- WAF·보안 경보
- 실제 Teams·메일 전달
- 장애 시 이전 버전 전환

## 6. 하면 안 되는 작업

- 운영 env/secret 파일을 메신저나 PR에 첨부
- 하나의 Entra app을 화면과 API에 함께 입력
- migration 실패 후 application 강제 시작
- 기존 migration file 수정·삭제
- 운영 DB 초기화로 오류 해결
- 사용자 승인 없는 실제 Teams·메일 테스트

## 7. 현재 상태

- 자동 검증: 완료
- 사용자 검수: 대기
- 실제 공개 서비스: 미선정
- 공개 배포: 아직 불가
- 다음 단계: Azure 서비스·domain·DB·WAF·SIEM·rollback 방식 결정
