### 직접 검증과 한계

실제 `AuthLoginScreen`을 임시 로컬 확인 entry에서 렌더링해 PC 1440×810, 모바일 402×852·390×844, 짧은 390×600을 직접 확인했다. 모바일 카드 x50/y277·301×298, LOGIN x119/y473·164×33, 점 패턴 x239/y672·163×180을 DOM 실측으로 확인했다. 짧은 화면은 세로 스크롤을 제공하고 가로 넘침·빈 화면이 없다. 상태 유지 체크 해제와 모바일/PC 로딩 표시를 확인했으며 확인 탭의 console error는 없다.

인증 테스트 25개, frontend build(TypeScript 포함), 변경 App ESLint를 통과했다. build에는 기존 대형 bundle 경고가 남는다. 실제 Microsoft 로그인은 실행하지 않았고 전체 회귀·required CI·원격 반영·배포는 이번 로컬 확인과 구분한다. 현재 결과를 지정 화면 전체의 100% 동일 구현 완료로 확대하지 않는다. 한글 fallback 및 브라우저 렌더링까지 포함한 최종 동일성 판정은 VALIDATION의 같은 폭/상태 비교에 남긴다.

검수 runtime은 기존 5186 frontend/5096 backend와 DB를 보존했다. `http://127.0.0.1:5186/login-review.html`은 실제 컴포넌트의 화면 확인용 임시 entry이며 Microsoft 로그인 요청을 보내지 않는다. `?loading`으로 로딩 화면을 확인할 수 있다. 임시 `frontend/login-review.html`·`frontend/login-review.tsx`는 커밋·제품 build entry에서 제외한다. 제품 검수는 기존 `http://127.0.0.1:5186`을 사용한다.
